# 需求：独立、可配置的 Local Hand

- Authority: Owner；Status: DRAFT / 待确认；阶段: S1。
- 来源基线: `10d2a5c827964989f41ca6e8eeac3d44de6d0f04` 中的现有 Local Hand，实现与证据按 [迁移记录](FORMATION_AND_MIGRATION.md) 分开处理。
- 本文为需求唯一权威入口；架构和实施方案不得自行扩大它。

## 问题和使用者

现有执行器与工程 SOP 同仓，部署默认值绑定具体用户、仓库和节点；外部使用者难以安装和复用，升级也容易把治理记录、机器状态和产品版本混为一体。目标是让维护者用显式配置部署同一份产品，让控制端通过稳定任务接口完成有限本机操作，并能判定结果来自哪个任务、哪份代码和哪个节点配置。

首个已存在的控制端是 ChatGPT 所在的控制流程；未来 CLI、其他模型或自动化控制端通过相同协议接入。Linux 和 Windows 是平台，不作为“两个独立 consumer”来虚增复用证据。artifact-ledger A2 是后续具体使用场景，尚未由新包完成验收。

## 阶段边界

| 阶段 | 交付 | 本轮范围 |

## 功能和可观察结果

| ID | 需求 | 验收结果 |
| --- | --- | --- |
| R01 | 独立安装：运行和构建不导入 SOP 或历史控制实验模块 | 从新 checkout 构建 wheel；全新 runtime venv 在源码目录之外执行入口；导入路径来自该 venv |
| R02 | 配置覆盖节点、项目根、仓库白名单、验证配置、mailbox 目标及平台运行路径 | 两套无真实身份的配置使用同一包和同一校验器；更换合法部署值无需改产品源码 |
| R03 | 保留有限 Task/Result v1 契约 | 八种动作均有正向和拒绝路径；未知动作、字段、缺失或 null 参数拒绝；错节点任务不执行 |
| R04 | 结果可关联且可解释 | 控制端核对 task ID、digest、action、target/node 和预期来源；区分 succeeded/failed/rejected/stale/indeterminate |
| R05 | 保留文件边界和 CAS 语义 | 越界、别名、符号链接和 Git 元数据访问拒绝；旧摘要产生 stale；成功后独立读回摘要一致 |
| R06 | 固定验证 profile 有明确资源上界 | 任务只能选预先批准的 profile；超时处置子进程树；输出限额生效；无法确定清理完成时不报成功 |
| R07 | 崩溃与重复投递有可审计处理 | 收据、outbox 和冲突记录可恢复；相同 ID 的不同内容不覆盖；controller 等待超时不自动重发有副作用任务 |
| R08 | 包、代码和部署身份分离且绑定 | wheel SHA-256、源码提交、core package digest、原始配置 digest 与 install UUID 各有独立证据；安装模式不靠工作目录猜版本 |
| R09 | 跨平台语义一致 | Linux/Windows 共用协议和核心；Windows PowerShell 7+；5.1 在持久化变更前明确拒绝；真实平台缺席则该项未验证 |
| R10 | 公开候选最小、可审查 | 逐项来源清单、公开扫描与人工检查；不携带凭据、私有历史、原始节点证据或机器专用迁移脚本 |
| R11 | 升级保留回退与环境隔离 | S1 不覆盖或删除现有 venv/checkout/state；S2 在新目录验证后才切换，旧版及证据保留 |
| R12 | 证据可复核 | 每项记录命令/argv、cwd、UTC 时间、耗时、退出码、环境版本、日志、摘要和 RSS；不支持的测量明确标记，不填 0 冒充 |

八种动作固定为 `node.status`、`repo.audit`、`fs.list`、`fs.read_text`、`fs.write_text_cas`、`git.status`、`git.diff`、`validation.run_profile`。本阶段不添加通用 shell、桌面控制、git 写入、merge、发布或 NAS 操作能力。

## 约束与不可接受结果

只支持可信单控制端、可信仓库代码、scratch／非敏感数据。验证程序以运行账户权限执行；cwd、超时和环境清理不构成 OS 沙箱。部署者必须用 OS 账户及权限划定范围，不能把 `validation.run_profile` 宣称为执行不可信代码的安全边界。

Task v1 不携带模型身份或授权声明；权限来自准入后的部署配置和受控传输。参数化不得把固定白名单变成任意 URL、任意路径或任意命令。多控制端、通用插件加载、互联网开放入口、加密控制端身份/防重放协议、macOS、敏感或生产工作负载不属于 S1。

CAS 依赖 cooperative single-writer 边界和第二次检查；不能承诺对不合作编辑器的线性一致性。进程中断期间的副作用无法确认时保留 indeterminate，不能用新任务 ID 自动再执行来消除不确定性。

不能把旧版实机 PASS、CI fixture PASS 或配置文件存在，当作新版 service 已部署并完成恢复验收。公开空仓不代表 Formation、实现、发布或实机 Gate 已关闭。

## 成功条件与待决事项

S1 成功须同时满足实施方案 V01–V10 中的必需证据、无未解释的测试退化、无真实部署污染，形成候选包及其公开审查清单。若缺 Windows runner，允许完成 Linux 部分，但 S1 跨平台验收保持未完成。

许可证由 Owner 在源码公开前决定，并保留来源所需 notices；它不阻塞本地文档和经 Gate 授权的隔离实现。公开规则摘录当前为候选；S1 executor 可使用固定 Private companion source，后续公开采用不得静默替换规则来源。多仓库根相互包含/别名的新增保障和更严格 JSON 解析属于后续单独范围；本版公开材料须明确这些未闭合边界，不能扩大威胁模型。
