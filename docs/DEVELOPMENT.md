## PR #50 读取边界复核（2026-10-22）

对已合并的 [PR #50](https://github.com/kongbu0621/infra-local-hand/pull/50)
继续沿挂载观察、目录描述符、原账本、封存文件和本机入口复核，复现并修复三类问题：

- 挂载观察原先先完整捕获子进程输出，再检查限额。现在边读取边限额，
  不积累 stderr，并在超量、超时或读取失败后分别回收子进程、管道和 selector。
- 父目录切换时，关闭旧描述符报错会泄漏已打开的新目录，甚至再次关闭已被复用的编号；
  目录及 authority 读取的清理错误还可能覆盖原始校验错误。现在先转移描述符所有权，
  独立关闭并保留首个错误，失败后可以重试；私有入口的受保护配置读取也修复了同类问题。
- 配套私有入口每次查询重建读取器，随机游标密钥随之变化，导致同一 MCP 连接的第二页
  证据清单失败。私有修复在连接内复用密钥，继续逐页核对调用者和证据目录；新连接仍使
  旧游标失效。公共组件不增加部署路径或机器配置。

查询只选择单挂载点的 7 个字段；合成挂载表中一个 3,856 字节的合法路径经控制字符
转义后输出 23,288 字节，原 16 KiB 会误拒。按 Owner 选择将上限
调整为 256 KiB，保留 5 秒超时，拒绝超过限额的第一个字节，正常文件读取不受此限额影响。

旧实现反例及修复后结果均保留。源码读取与既有只读检查 37 项通过；候选组件加载原
安装核心的 32 项检查通过，包含原有分块读取、拒绝后重试及反复构造失败后的资源释放。
真实临时子进程覆盖 256 KiB 前后边界、长路径转义、stderr 超量、EOF 前后超时及清理故障；真实临时
封存文件覆盖跨读取器分页、权限和篡改拒绝。私有入口回归 12 项、分页检查 3 项通过，
同组分页检查在原安装核心下亦通过；私有配置清理检查 3 项及安装器备份、失败后继续和
版本化切换检查 9 项通过。
编译和差异格式检查通过。上述封存检查使用临时数据，不代表真实任务执行或封存验收。

安装方案为新连接选择版本化读取器，已有连接使用的旧文件保持。部署配置、安装过程、
备份和现场验收结果在私有配套仓库维护，不随本次公共修复发布；原发布标签保持原提交。

## 控制器退出后的未下发任务收尾（2026-10-22）

现场回传的只读诊断显示原控制器已退出、管理器没有保留阶段，账本仍为待恢复的
排队状态。原 `TaskService.recover()` 依赖存活控制器及其通道，不能在控制器退出后
直接重跑旧启动命令。新管理员入口
[`unstarted_recovery.py`](../tools/admin/local_hand_system_manager/unstarted_recovery.py)
仅处理同一次启动环境中、原请求已落账但没有任何阶段下发的情况。

入口核对受保护的 current、原启动意图、动态控制器身份、退出／双流 EOF 记录及
空管理器快照；账本所属普通账户独占原 authority 锁，root 才重新观察同一 invocation、
不可自动重启的控制器配置，以及原执行、配额查询和管理 cgroup 全部为空。
SQLite 不由 root 打开，普通子进程清空继承描述符、附加组及能力并设置 NoNewPrivileges。
任何身份冲突、实际下发记录、缺失执行标志、忙碌进程树或输入变化都不能放行。

符合条件时复用原 `TaskSession` 收尾事务：只追加 `RECOVERED_BEFORE_START`，
结果为 `TERMINAL / EXITED / UNKNOWN`，证据仍为 `STAGING`；只释放执行 owner 的租约，
保留原请求、预算、准备及目录保护租约、全部旧事件与现场文件。不开新阶段、不提交新任务。
最终回复或归档失败时可对同一原任务重复核对，已有收尾返回 `ALREADY_COMPLETED`，不再次写账本。
默认只检查，显式 `--apply` 才收尾；每次另建私有检查归档，不覆盖旧件。

## Server 的源码在哪里

服务用 Python 实现，MCP SDK 处理工具声明与协议消息，Uvicorn 提供 HTTP 服务。
本项目的 MCP 网络入口使用 Streamable HTTP 传输，也就是通过 HTTP 交换 MCP 消息，
并验证访问令牌；本地 CLI 则通过 Unix socket 和操作系统身份映射访问后端。
两者共享任务逻辑，传输方式和入口鉴权方式各不相同。

命令 `local-hand-mcp` 在 [pyproject.toml](../pyproject.toml) 中映射到
`local_hand_mcp.server:main`；启用该入口需要安装项目固定的 `[mcp]` 可选依赖。
`main()` 加载配置、认证器和后端，由 `create_app()` 创建应用，再调用 `uvicorn.run()`
监听 `127.0.0.1`，端口由必填的 `--port` 参数指定。外部 HTTPS 入口转发到配置的端口。
这里的“本地”指任务执行位置；客户端仍然可以通过网络访问这个服务。

| 源码 | 职责与阅读入口 |
| --- | --- |
| [server.py](../tools/local_hand_mcp/server.py) | `main()` 启动服务；`create_app()` 注册工具、处理 MCP 请求并返回结果。 |
| [auth.py](../tools/local_hand_mcp/auth.py) | `JWTVerifier` 验证访问令牌和调用者身份。 |
| [resident.py](../tools/local_hand_mcp/resident.py) | `ResidentBroker.call()` 将常驻入口的请求送到对应任务或历史结果。 |
| [resident_service.py](../tools/admin/local_hand_system_manager/resident_service.py) | `ResidentService` 准备任务资源；管理服务通过受保护的本地 socket 接收请求。 |
| [task_service.py](../tools/admin/local_hand_system_manager/task_service.py) | `TaskService` 启动并管理一个任务的服务及阶段执行。 |
| [broker.py](../tools/local_hand_jobs/broker.py) | `Broker` 管理提交、取消、状态、资源及持久账本；相同任务 ID 与摘要复用已有记录，相同 ID 携带不同请求会被拒绝。 |
| [runner.py](../tools/local_hand_jobs/runner.py) | `Runner` 与进程管理器管理实际执行进程、停止和结果收集。 |

先读 `server.py` 的 `main()` 和 `create_app()`，再顺着 `ResidentBroker.call()`
查看任务路由，就能把网络入口与实际执行连起来。
在 `--resident` 常驻模式下，MCP API 与负责准备资源、启动任务的管理服务分别运行，
通过受保护的本地 socket 通信；表中的模块并不都运行在同一个 Server 进程里。

`preparation`，以新的任务 UUID 调用 `lh_job_prepare`，READY 后把返回的 `request`
原样交给 `lh_job_submit`；PREPARING 用同一 UUID 查询准备进度。准备需要 `lh:submit`，
只读查询不会创建任务。失败准备保留原件，修复后可用 `retry_failed=true` 沿同一任务重试；
已提交业务及不确定的执行不会因此重放。
常驻服务按当前启动环境绑定新任务的资源，并继续只读返回已完成任务。现场配置仅开放
`host.inspect`，同时一个执行会话，最多保留 32 个任务；前一会话退出前返回 RESOURCE_BUSY，
稍后沿用原任务 UUID 重试。原只读配置和安装保留，开机入口已切换到常驻服务。
刷新连接后，ChatGPT 已完成重启后新任务的自动准备、提交、执行和完整结果读取；准备一次、
账本接收一次，绑定当前启动环境，原任务未重放。ChatGPT 的运行中取消及同任务恢复尚未现场验证。
已退出的历史失败单元经实际状态核对后不再封锁新任务；停止后的单元回收不再要求补造终态快照。
