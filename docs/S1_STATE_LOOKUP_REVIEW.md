## 已复现的问题

共享 target_lexists 原先直接使用 os.path.lexists；后者把 lstat 的 OSError 转成 False。调用者因此无法区分“文件确实不存在”和“文件存在但读取状态失败”。在合成 Git mailbox 中注入指定路径的 EIO / EACCES，复现如下行为：

| 链路边界 | 原实现实测 | 修复后 |
| --- | --- | --- |
| 已完成收据读取失败，远端 Result 已丢失 | 再次调用执行器，已有收据未阻止重执行 | 返回 indeterminate，收据原字节保留；恢复后只重新发布原 Result |
| 本地冲突标记读取失败，远端冲突已丢失 | 被阻止的 Task 仍调用执行器 | 返回 indeterminate；恢复后补发冲突，不执行 Task |
| 旧隔离文件状态读取失败 | 新文件覆盖旧证据 | 保留两份原文件；恢复后分配后缀并保存新证据 |
| controller 读取匹配冲突的状态失败 | 把冲突当成不存在，最终等待超时 | 明确报告 path_state_unavailable / indeterminate |
| 已发布 Result 的状态读取失败 | 继续尝试创建目标，最终报告目标被占用 | 在状态检查处停止；outbox 保留，恢复后核对并清理 |
| 不存在、悬空符号链接、EIO / EACCES / ENOTDIR | 错误状态也返回不存在 | 仅 FileNotFoundError 返回 False；悬空链接仍视为存在；其他 I/O 错误停止 |

六个新用例在输入 main 的原实现上全部 FAIL，最终候选上全部 PASS。前两个用例实测执行器被错误调用一次；隔离用例实测旧字节被覆盖。失败复现使用单路径文件系统故障注入，没有扩大远端 allowlist、修改 Task 协议或使用真实机器任务。

## 修复与验证边界

共享检查现在显式执行 os.lstat，只把 FileNotFoundError 当作不存在。其他 OSError 保留原异常链和 errno，并以 path_state_unavailable / indeterminate 返回。可选 mailbox 控制目录也使用同一判断，避免保留另一个吞错入口。

首个辅助实现使用 Path.lstat，而故障注入针对 os.lstat；Python 3.12 的 Path.lstat 实际通过 os.stat(follow_symlinks=False) 执行，导致注入不再覆盖目标调用，首次修复检查仍为六个 FAIL。随后将实现固定为原路径查询使用的 os.lstat，并重新执行用例。该失败轮次、辅助实现版本、日志和退出码全部保留，没有把它改写为 PASS。

不宣称修复一般并发文件系统竞争；依然要求现有单 active worker/state-root 与受信本地状态目录。操作失败不会被当作任务执行失败或成功。Worker --once 和 controller wait 的状态不确定均实际返回退出码 3。
