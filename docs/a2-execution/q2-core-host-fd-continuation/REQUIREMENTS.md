## 必须一起解决的问题

[离线复核](../Q2_CORE_HOST_FD_REVIEW_20261009.md)证明，保留旧09b后，单进程到完成阶段
至少需131个长期 FD，超过128；原双份历史的标记样本为66121 B，超过65536 B。
已完成的普通修复能在消费前拒绝缺额，但不能使这个集合适配。仅延后 selector、关闭
证据后重开、增加限额或删减历史，都不是本方案。

交付仍只有正常任务及结果、运行取消和同任务恢复：H01→Q4→H11。
为此，本批次把55件旧维护证据的连续 FD 持有转给一个同权限的有界子进程，并对重复历史
采用可完整还原的摘要引用。所有原件、检查、旧 UNKNOWN 和消费义务保留。

## 请求批准的一个完整批次

- FD1：实现架构规定的 FD 所有权交接、父子进程累计计量、完整生命周期准入、标记历史
  去重和两端独立验证；追加旧09b的准确失败 profile；完成离线回归、保留来源/成本/包大小
  验证、main 发布、准确 D 首次 CI、独立安装及维护与条件核心两份 caller 冻结。
- FD2：仅一个新维护 `lhqjgrow-20261009c`，沿用已采用 VM、安装、五盘和原配置。
  最多两次原连接 SSH、一次经验证的正常关机、一次维护内启动及原 journal 256→512 MiB
  增长；保留 RT 已批准的每 boot 固定运行时准备。完整静止/数据检查通过后才允许变更。
- FD3：只有 FD2 所有成功原件完整验证后，才发行同一个未发行 `lhqcore-20261007a`，
  在原 live finalizer 顺序执行 H01→Q4→H11。维护失败时三例保持 NOT_RUN。

本地连续完成整批，范围内不逐步骤再批准。一次失败即停止并保留；不重试、补采、停止业务
服务、重装包、清理、回滚、恢复或追加窗口。旧 caller 全部不可重放。原正常关机条件和
单次 maintenance restart 不能被用作失败后的额外 VM 启动。

## 保护与资源边界

55件旧维护原件先在父进程按原规则打开和验证。fork 继承后，子进程以原 FD 完成确认；
父进程收到与准确集合绑定的 READY 且确认子进程存活后，才关闭自己的55个副本。
同一 open-file description 始终至少由一方持有；不能通过关闭所有副本再重新打开来替代。
child 死亡、持有不完整、超时、回复错配或名称/身份/bytes/SHA 漂移均停止，不换进程重试。

这是对宿主进程安排的明确变更：每次调用至多一个前台 custodian；同窗预检与执行各自
持有，调用结束即收尾，不并行遗留。它不提供特权、网络、命令执行、任意路径请求或后台服务。
父进程保留其它原始源、核心/诊断/容量证据、工具、VM 和输出的原 FD 与全部检查。
总 FD 槽位会分布在两个进程中，不能宣称系统合计槽位没有增加；每进程仍受128上限约束。

原维护900/780秒、管理累计CPU120秒/RSS512 MiB、AS256 MiB、FD128、最多8个同时存在的
控制子进程、VM4 vCPU/8192 MiB保持。新子进程的存活 CPU/RSS、退出费用及同窗预检费用
全部计入原累计预算，不能把 fork 的另一份 RSS 记零，不能另开额度或时钟。
父子保留原期限；新子进程不接收 reset。计量不完整即拒绝继续。

guest 保留准确 Q1、19/7/7声明域、process/writer/根目录、quota/ext4/UUID/内容保护。
trusted-single-admin、declared-startup 前提保持；unknown/矛盾即停。减少的未知启动观察
仍不等价于连续排除。已有正确运行时对象复用，准备每 boot 最多12命令/60秒，原配置与
运行时费用保持；不增加 guest 探查、业务启动或管理例外。

十二代维护完整义务为 **15552 MiB / 4440 inodes / 1440 CPU-s**；加原核心捕获后宿主
底线 **15616 MiB / 4456 inodes**。新子进程费用来自本代原预算，不产生第十三代或退款。
原单流1 MiB、捕获8 MiB、marker/transition65536 B、短预检4096 B、双源各98304 B、
guest bundle49152/393216 B、核心32 MiB包和1 MiB approved-input限制保持。
固定 custodian 源成员≤16384 B；它只在宿主运行，仍须绑定完整来源且计入相关包上界。
