## 唯一算法差异

继续使用现有普通 coordinator、固定生成的 root writer 和两阶段 guest 协议。
`tests/e3_host/q2_journal_growth.py` 的 `collect_image_writers` 对每个 task 依次完成原
FD/flags/身份复核、maps 读取及解析、task 身份复核，再完成原 task/PID 集合复核。
只把 maps 累计比较的固定 cap 改为 512 MiB；累计方式、检查位置、失败 reason/errno、
PID/TID 安全编码和所有其它谓词不变。超过新 cap 仍在解析该份 maps 之前失败。

`q2_journal_growth_guest.py` 继续从准确 host 源提取原函数生成 payload；不另写一份 scanner，
不在 root 下 import 可写工作区。准确新 A/C、文档摘要和祖先校验加入已有 admission 与
manifest，同时保留全部旧 pins；D 必须承接独立 C，closure 本身不能当执行候选。
固定五字段失败协议、长度约束及父层严格校验保持；不增加返回字段或机器原文。

## 预算含义与边界

512 MiB 是单次扫描累计已完整读取的 maps 文本接受额。它不是申请 512 MiB 缓冲区、
落盘额度或物理内存证明：实现依次处理每份 ≤1 MiB 的文本，不保存历次 maps；当前文件
和解析临时对象仍有内存开销，原 AS/RSS 检查继续生效。PID/FD 元数据的原开销保持。

比较在一次文件读取后进行，因此一次拒绝的累计值可最多达到 **513 MiB**。若触发的是
单文件长度限制，其有界探读最多额外读到该文件的 1 MiB+1 B，然后停止。不得把累计
接受 cap 描述为包含拒绝探读的严格总 I/O 上界，也不将 maps 数字充当其它 proc 读取计量。
八个全成功检查点的 maps 接受总量最多 **4 GiB**；每检查点只调用一次，失败不进入下一
检查点。包含拒绝读取时，单次至多 513 MiB+1 B；七次成功加末次失败的整个窗口至多
4097 MiB+1 B（4,296,015,873 B）。这些只界定 maps 读取，不界定内核的全部工作量。
既有时间/CPU 限制仍可能先拒绝，不为吃满字节预算延长期限；原协作式 deadline 检查
也不保证不可中断读取及时返回，不能将超时当成子进程已被强制终止。

各 writer 的 15s 双钟期限、900s/780s、AS 256 MiB/FD 128、维护观测 120 CPU-s/512 MiB、
最多八控制子进程不变。writer 输入/stdout 各 65536 B、stderr 4096 B、payload 32768 B，
两维护实现各 65536 B；不新增第三实现或依赖。原设备可用 1296 MiB/370 inode、
历史承诺 264 MiB/80 inode、备份 320 MiB、镜像 576 MiB、capture 8 MiB/32 inode 保持。
更早用量 UNKNOWN、计量覆盖限制与原备份/维护失败风险不因本修正消失。

## 路线选择和未证明项

- 不选“只加 6,778 B”：首次越界量不是全量需求，会把未知伪装为精确缺口。
- 不选去重、仅看进程首线程或缓存上次结果：这会改变既有逐 task 观察及其时间覆盖，
  并要求另一套正确性证明；不能顺带减少 FD 扫描或漏掉映射 writer。
- 不选取消累计限额或按 65,536 tasks ×1 MiB 放到 64 GiB：理论组合上界不能作为合理
  现场预算。固定 512 MiB 提供八倍余量并保留独立字节界；它是有待批准的取舍。
- 不以新探针测完宿主再决定 cap。真实全量需求和耗时尚未知，本方案接受一次有界验证
  仍可能因字节、时间、drift 或其它原门失败的风险，不逐级自动调参。

这项观察仍不是原子快照或排他锁；维持原管理信任与正常镜像锁，不能宣称它排除了后续
所有写入。没有新 kernel 机制、平台拦截规避逻辑或安全资格申请。
