# Journal proc 诊断替代窗口计划

状态 **PROPOSED / Gate OPEN / NOT APPROVED**，仅 DR1–DR2。
遵循[需求](REQUIREMENTS.md)和[架构](ARCHITECTURE.md)；本文不包含现场命令或可执行原型。

## DR1 修复验证与准确候选

先在已有开发授权内完成诊断修复并发布。离线验证覆盖每个 proc 限制位点的初读/复核、
原拒绝阈值不变、源 scanner 与生成 payload 一致、首次拒绝值/原 cap/适用 PID/TID、
父层保留及无额外读取；保留五字段 schema 和全部隐私、长度、计量约束。
不以真实 sudo 或宿主全局 proc 扫描测试修复，不宣称恢复旧现场分支/计数。
准确修复提交及实际验证/CI 结果由独立登记记录；pending、SKIP 或不支持均不计 PASS。

将本提案三文档独立冻结为准确 A；另行登记准确 SHA。只有 Owner 明确批准该 A 及一次
替代窗口后，才记录准确 B 并提交独立 bookkeeping-only C；C 不含实现、配置或现场操作。
随后 D 承接 C，完成本范围准确授权绑定和受影响验证，冻结源码/payload/argv/原输入，
确认最终执行候选对应的相关 CI 已通过。现有开发权限不暂停；开发 PASS 不授权 DR2。

## DR2 单次预检，条件完成原维护

Owner 在既有真实本机前台终端就绪，原静态输入和 TTY 资格通过后，才开始唯一替代窗口。
沿用原 session、输出名、本人直接 sudo 认证及同窗两 CLI 交接；每个原 writer 检查点仅一次。
不提前发权限/端口/proc 探测，不把首个观察作为可重复的诊断试跑。

原预检全通过后，在同一窗口完成尚未消费的原 journal 维护。任何失败、未知、超时、绑定
漂移立即停止；未创建 marker 也不返还窗口。新安全诊断只解释本次首次拒绝，不改历史 UNKNOWN，
不触发阈值调整、扫描裁剪、预算增长、补采、重试或另开窗口。

据原 receipt 如实记录准确候选、窗口、维护动作计数、退出/保留状态、内容与容量结果；
没有合格 receipt 不记扩容成功。失败不自动重连、强杀、清理、回滚或重启 VM。
本范围不执行 H01/Q4/H11；只在维护真实完成后准备下一步核心验收，支线继续暂停。
