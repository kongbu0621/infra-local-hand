# Journal proc 诊断替代窗口架构

状态 **PROPOSED / Gate OPEN**；范围仅来自[需求](REQUIREMENTS.md)。
复用既有 CLI、root writer、终端认证、八检查点、两阶段 guest 协议及上一方案的
[架构](../q2-core-journal-diagnostic-resume/ARCHITECTURE.md)，不引入组件或新现场读取。

## 诊断变化与执行边界

离线修复使源 scanner 和生成 payload 在同一个原拒绝点保留固定类别、首次拒绝值、原上限及
适用 PID/TID。初读及复核使用相同规则。只使用该失败判定已经取得的数据；不另读 proc，
不枚举剩余条目以计算全量值，不返回私密路径、maps/cmdline/environ 或任意异常原文。
首个拒绝值可能是有界扫描刚超限的值，不冒充宿主总量或推断完整缺口。

失败报告保持既有五字段 schema、有界 reason/errno、请求绑定、父层严格校验和计量。
缺失、畸形、截断或不匹配仍拒绝；诊断内容不构成成功报告，也不代替 EOF、真实退出、
身份一致、完整扫描及所有原准入条件。更具体的 reason 不改变任何 cap、覆盖或预算。

新的执行候选 D 必须承接本范围独立 C；如需实现授权绑定，仅加入本范围准确 A/C 并保留
全部旧 pins、文档完整性及祖先校验。冻结准确源码、payload、argv、工具和原静态输入。
旧批准文档、失败记录及交接证据保留，不改摘要、换名、换 session 或复用旧 PASS 来重开窗口。
源码长度及全部原 I/O 限额保持；不得以删检查或增加读取为绑定/诊断腾挪空间。

## 唯一窗口及原维护

先完成原静态准备和 TTY 资格校验，不发 sudo/SSH、不创建 marker。新预检开始才建立唯一
900s/780s 双时钟窗口；execute 仅接受同次私有绑定。发现旧目标、超期或任何原漂移即停。

全门通过后，同窗沿用正常关机、确认退出/离线、完整备份、一次镜像增长、一次原配置启动、
原被动等待、一次 ext4 增长及内容/容量验证。原锁、双阶段 SSH、令牌和 mutator 不能强杀
制造期限保证的边界不变。完整预算沿用前述架构：每相关设备 1296 MiB/370 inode 条件、
旧承诺 264 MiB/80 inode、备份 320 MiB、镜像 576 MiB、capture 8 MiB/32 inode、
120 CPU-s/512 MiB 部分观测、AS 256 MiB/FD 128、最多八控制子进程；
writer 输入/stdout 各 65536 B、stderr 4096 B、payload 32768 B、两维护实现各 65536 B。
这些都不是新增预算；历史用量和管理祖先/TTY 计量限制及 UNKNOWN 不变。

失败保留已验证的首个具体原因和已发生动作，不通过另一次观察解释失败；超时或管道关闭
不冒充子进程退出，晚到认证仍受原 root deadline 拒绝。不自动恢复或进入业务核心执行。
