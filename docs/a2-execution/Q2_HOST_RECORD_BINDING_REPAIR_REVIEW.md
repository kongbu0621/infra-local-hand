## 问题与修复

| 边界 | 原问题 | 本次结果 |
| --- | --- | --- |
| 意图与预检 | 目录 UID/GID 只检查整数范围，未与现行 root-only writer 的生成条件及父设备绑定 | 严格绑定 root 身份、同一父设备和不同父 inode；同步重算 JSON/hash 也不能放行矛盾身份 |
| 账单中的 marker | 根身份及内容摘要之外，缺少部分类型、权限、链接数和叶项身份检查 | 目录必须为 0700/nlink2；意图必须为同设备、单链接、root 所有的 0400 普通文件；拒绝 inode 别名 |
| 写入期间身份 | 只在构造阶段检查 root，后续持有 fd 的操作没有持续核验 | 每个窗口 guard 重查身份；意图排他打开后、payload write 以前再查身份及准备期限 |
| 部分失败 | 需防止新检查被解释为可删除或重新消费 | 保留目录及空/部分意图；后继预检仍拒绝，原双钟不刷新 |

本轮没有扩大允许的 UID，也没有普通身份 v2、新的来源采用、读取例外或运行权限。
修正的原合成正例（普通 UID/0600）本来不符合 root v1 writer；准确合法 root v1 仍通过。
普通身份支持仍需完整身份/保护链及独立文件系统资格，不能仅删除 root 判断。
