## 目的与事实

原恢复已完成账户、配额、安装和装配，但首次监督服务启动命令包含无效的
`CPUQuota=100.0000%`，客户端退出 1。原 owner 请求已发行，子服务未进入，
原判定保持 INCOMPLETE。源码修复与 297 项回归、真实 systemd 解析器检查已完成，
见 [修复记录](../Q2_CPU_QUOTA_REPAIR_VERIFICATION.md)。

目标是在同一个隔离 guest 上换用准确修复候选，集中完成一次新的有限 Q2 实验，
减少逐命令交接，同时保留先前失败。原恢复 R05/R06/R07 固定旧候选且禁止重放，
不能把新的候选、身份及时间窗口冒充原恢复的未完成步骤。本提案单独请求该变化，
不重新审批不受影响的源码修复或原准备范围。

## 预算与决策

空间沿用原总上界，**新旧合计**：候选/安装/构建暂存 256 MiB，普通 state 与准备日志
32 MiB，管理 journal 64 MiB，管理捕获与声明 64 MiB。七个已准备项目保持原实际
各 1 MiB/128 inode，不增加硬限制；四个 Q1 域的 196 MiB 保留承诺继续计入。
文件系统唯一域计费与块/inode 开销必须可核查，空间不足即阻塞。

一次新增外层管理/捕获窗口 300 秒，guest service ≤270 秒、停止 ≤3 秒，
鉴证/安装/装配从 guest 入口起 ≤140 秒，owner ≤120 秒，内部保持原更小角色限额。
管理服务新增 CPU 上界 300 秒、内存 512 MiB、任务 64；独立运行域本批新增 CPU
总上界 400 秒、合计内存 1536 MiB、任务 1024。两者须分别计费并验证嵌套峰值，
不能用管理服务限制替代子域合计限制。外部两路捕获合计 ≤2 MiB。

需要 Owner 对准确 R/A 关闭本 scope，明确允许**保留已发行失败、换用固定修复候选、
使用鉴证未消费的原七根及一次新的 300 秒运行窗口**。该决定不改变原两次尝试的期限或结论。
