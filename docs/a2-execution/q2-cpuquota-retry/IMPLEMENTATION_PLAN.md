新工具拟分为 `q2_retry_contract.py`（严格私有计划/身份/预算）、`q2_retry.py`
（鉴证与 create-only 独立状态）、`q2_retry_delivery.py`（外层窗口与原 client）、
`q2_retry_driver.py`（一次编排）。这些仅为设计落点，尚未创建。
可复用既有 q2_prepare_build 安装核验、装配与 owner/chain；不得直接调用原首次准备或
账户恢复入口，绕过已存在检查。新 schema 设计为 `local-hand-q2-cpuquota-retry/v1`，
具有准确旧失败引用、新授权/候选/对象映射、issued/deadline、各域预算和失败保留字段。

N3 在任何本次持久修改前完成有界预检。通过后排他保存唯一新 reservation，逐步 append
intent/result；N4 不重设 quota、不初始化旧 ledger、不清理旧路径。正常 inactive 配置
可各 start 一次，记录真实新 cgroup 身份；需 restart/修改/新增依赖即停止。
普通代码路径必须对既有普通账户可访问，保护配置和账本按各自身份隔离。

所有新身份在一次私有计划中固定；新 authority 同时引用原准备、原失败和本 scope B/C/D。
原七根映射只有在同一鉴证记录中证明全部未消费才生效，不接受部分已用根混搭。
发行前再次检查截止时间、原对象保持、空树、空账本和容量；不足不发请求。

鉴证按真实初始化 schema 处理 SQLite：除业务表外，允许其固定自动索引、
`sqlite_sequence` 和不可变 trigger；不能把合法系统对象误判为未知表。
generation 必须保持原初始化值，revocations/sequence 也不得偏离原空状态。
store_parent 中存在已准备的 store 根是预期结构，应检查 store 根自身的成员，
不把父目录非空当作 payload 消费。现有诊断包未含数据库原文件或七根成员清单，
这些均须现场读取验证，不声称离线已证明。

## 窗口与费用实施

外层从首次探测前起 300 秒；guest ≤270 秒，stop ≤3 秒；guest 鉴证/安装/装配
从入口起 140 秒，owner ≤120 秒。内部 target/supervisor/operation 保留原更小限额。
同一绝对截止时间贯穿命令、捕获、停止与封存，不按阶段重新取 now 加预算。
本批管理 CPU≤300 秒、512 MiB/64 任务；独立运行域 CPU 合计≤400 秒、
内存合计≤1536 MiB、任务≤1024。最多外部双流 2 MiB；逐层输出仍按原更小限制。

N3/N4/N5 均核对新旧总空间。计入构建暂存、旧失败字节、源与 runtime、新账本/日志、
待写最终结果/封存及块/inode 开销；遵守需求的四类原总上界。实际使用量、剩余承诺和
唯一项目限额分别列账。缺容量直接 BLOCKED，不退款、清理或扩上限。

## 验证和完成定义

| 风险 | 必须验证 |
| --- | --- |
| 又遇 parser 或安装不匹配 | 真实 systemd 百分比解析、准确 wheel/source metadata、普通账户路径权限；来源/摘要错则拒绝 |
| 旧请求被伪装未发行或重放 | 原 rc/EOF/argv/未创建身份共同匹配；未知交付、已有子级、原 ledger 非空或 grant 消费即拒绝 |
| 新状态覆盖旧对象 | 原材料完整快照摘要、无别名/no-follow、create-only、并发败者及重复运行拒绝 |
| 根复用引入退款 | 七根真实身份/限额/成员、账本 generation 与空表绑定；任一 payload/消费或未知状态拒绝 |
| 隐式扩大预算 | 旧承诺累计、原域去重、块/inode不足、嵌套 CPU/memory/pids、安装增长和 seal 余量负例 |
| manager 生命周期被误判 | inactive 的准确配置一次 start；配置变化、failed、已有 job/工作、需 restart 均拒绝 |
| 超时或假完整 | 跨钟保守绑定、准备消耗窗口、guest 挂起、非零退出、缺 EOF、stop 失败、树不空、缺 seal 分别保留 |

N2 分开标明模型事实、真实文件/管道、真实 parser 和真实安装，只有 N5 能形成新的实机
Q2 证据。无需为本 scope 重跑 Q1 历史实验或 H06–H13。失败也交付结构化报告、原双流
与唯一保留目录；用户不需要删除文件再执行入口。

完成交付包括准确 D 与安装物、私有一次入口、N3/N4 回执、一次实际运行材料、外层原 client
退出/EOF 和分层核验。代码通过但未运行时明确报告 READY/BLOCKED，不能标为 Q2 完成。
本新尝试失败后只做保留式只读核验；第二次运行、候选再替换或扩大边界需另有明确决定。
