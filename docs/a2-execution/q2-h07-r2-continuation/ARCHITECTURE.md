## 研究变量与不变边界

第二轮在 probe 已执行 `B/cgroup.kill` 后复用同一 B/S/W，C1 的 S 在武装前以
SIGKILL 退出。该顺序与上游 `CLONE_INTO_CGROUP` 的 `kill_seq` 缺陷吻合；准确
Ubuntu 源码包缺修复已由[准确源码复核](../Q2_H07_ROUND2_KERNEL_SOURCE_REVIEW.md)确认，运行二进制与本次信号来源仍未动态证实。采用新世代不
把机制解释改写为已证现场根因，也不宣称对任意宿主或全部内核竞态提供解决办法。

新变量是每个固定实验使用独立的 cgroup 对象世代，保留共同 E 资源上限。修复
同时补齐早退诊断和失败报告；不能放宽原子入组、原 pidfd、账户降权、双钟、
原流 EOF、树空、独立 G 退出、六病例及清理判据。可信托管 OS、受审 T/G/S、
无外部 root 并行干预仍是明示前提。S/W 的过滤和权限边界保持，拒绝改成先运行
再迁移、交回外部 manager、改用用户当前 PRO6000 或原 guest。

原 A `71c7e842c724650a0e949a63bb898699b41107be` 及续验 A
`a08a5055c35009a896ad6c6059d709758cc78436` 的原文和历史标签保留。新 helper、
世代台账和 schema 属于新受影响范围；不能从旧 U2 的“不改 native helper”中
推断本次已获许可。未受影响的账户观察、工具权限和预算合同继续生效。

## 组件、控制权与固定接口

| 组件 | 本次职责 | 保持的边界 |
| --- | --- | --- |
| 外部 fixture T | 共同 E、账户、唯一活动世代、原 helper 进程、账本、阶段预算、最终清理 | 不恢复死亡 G，不重跑 probe/病例，不据报告总布尔值授予下一代资格 |
| C helper 内的收件侧 | 从固定例号选择准确世代对象，保留 held FD 身份、原流、原 G pidfd 与退出 | 不接收调用者选择的 cgroup 目标或任意命令 |
| G | 在世代 G 叶内固定双钟，只创建一次 S，关闭本代 B，保留明确拒绝/退出事件 | 关门不可逆，不能向下一代或旧代再注入 |
| S/W | 沿用固定合成角色与原子入组、降权、FD 和 seccomp 合同 | 无新路径、manager、网络或通用任务接口 |
| 独立收件器 | 显式版本校验、世代身份与账户绑定、事实派生、失败和清理分列 | 缺失的 launcher 身份保持未知，不以外部清理补 fence |
| 新 continuation 分支 | 绑定唯一被接受的历史事件、新 A/C、来源、实际轮次与前序 boot | 不将任意 UNKNOWN 转换为可重试，不读取“previous safe”布尔值 |

helper 仍只有固定 `probe`、固定 `case C1` 至 `case C6` 和非特权自检入口。
fixture 传入的 E 必须是本 run 登记的准确路径；helper 从 probe/case 枚举自行
推导子目录，不添加可选目标路径、自由前缀或额外 case ID。原 uid/gid 参数仍须
与本轮已准入账户绑定。新版本的返回对象、退出码和原进程退出分别记录。provenance另记录一次uname取得的完整kernel_version（最多1024 UTF-8 bytes），只补版本事实，不查询/安装软件包，不把它等同内核二进制摘要或动态归因。

## 七个世代与共同 E

E 全轮只创建一次，仍位于原限定的 `/sys/fs/cgroup/q2-h07-<run>-1-r3`。
不增加世代父目录。允许的相对名是以下完整集合；仅前缀相似不构成允许：

| 世代 | G 叶 | B 子树及其两叶 |
| --- | --- | --- |
| PROBE | `G-PROBE` | `B-PROBE`、`B-PROBE/S`、`B-PROBE/W` |
| C1–C6 | 对每个固定 i，`G-Ci` | `B-Ci`、`B-Ci/S`、`B-Ci/W` |

每代四个对象，至多七代，共同 E 加各代合计最多 **29 次 cgroup 对象创建**；
正常及失败路径都只能有一个未完全退休的世代，因此最多 **5 个仍可见/可使用的登记目录对象**。
这些是额外明示的 cgroup 对象数量界，不把普通文件 128 项上限偷换为 cgroup
总量证明。setup 部分失败也计入已创建数量；不补创建、重用名称或新增第八代。

`rmdir` 后内核可能仍有 dying/RCU/CSS 延迟释放对象，因此5不是内核尚未释放对象或其内存的上限；全轮累计创建最多29为该类对象提供有限总量。退休只证明原控制能力、进程、流和用户态登记对象已结束，不证明所有内核元数据即时回收。该元数据属于明示的lab设施成本，不由E的memory.max自动证明完整计费。无需另加dying归零等待或额外窗口来掩盖这一限制。

E 的 128 MiB、swap=0、32 tasks、单核速率保持。每代 G 64 MiB/4 tasks、B
64 MiB/16 tasks，均受 E 的共同上限；S/W 沿用原继承方式及至多 8 个后代。
只在 E 和本代 B 启用原固定控制器，不修改共享祖先。专属 UID 的必要写资格
只配置本代 B 和 W 的 `cgroup.procs`，不增加目录创建或外部委派权限。

名称不复用用于区分对象世代，但路径字符串不是对象身份。每项账本至少绑定
run/attempt/round、世代、固定相对名、创建顺序、held FD 的 dev/ino、实际限额、
创建/核验双钟和退休结果。历史上 dev/ino 可能再次分配，不能要求或声称它们
全轮永久唯一；同一时刻的别名必须拒绝。native 的五个 held FD 身份必须与
该代和共同 E 的记录一致，不允许从任意另一代借用匹配字段。

世代状态只有：`未创建 → 准备中 → 已准入 → 已执行 → 退休中 → 已退休`。
部分创建、身份漂移、原进程未决、EOF 不明或退休失败转入保留失败并停止；没有
回到已准入或创建下一代的边。probe 也必须完整退休，不能只在 probe 后清空
一次并继续复用六病例对象。

## 世代退休与错误传播

进入下一代前，T 必须同时取得：该次原 helper 已退出及原 stdout/stderr 完整
EOF；本代原收件结果足以满足原继续条件；所有登记进程均无未决；G 叶与 B
子树为空；本代最后资源采样与 held FD 身份核验完成；四个目录按 S/W、B/G
的子先父后次序成功移除，相关 held FD 全部关闭。probe 必须派生 supported；
病例必须原预期满足且清理已证，C3/C6 仅沿用既有有限例外。C6 固定最后执行。

FD 与路径在退休时再次核对，不能以旧 fd 指向已脱离命名空间的对象来代证当前
同名路径。只有在旧代全部关闭后才建立新代；独特固定名字、原进程退出、FD
关闭及移除证据共同防止错误复用，不声称单个 inode 或 `rmdir` 自身证明完整
进程封闭。任一步失败不递归删除陌生对象、不猜测替换身份、不建立下一代。

退休账本是追加记录；移除成功后从“当前可清理对象”集合退出，不能删除历史
条目。最终 cleanup 同时核对已退休记录和仍登记的活动/部分创建对象，仅操作
后者及 E、账户、构建对象，避免把第二次删除的 ENOENT 当成功或重复记功。
最终 E 的 kill 只用于停止和收尾，此后无新进程创建路径。清理是否有据与实验
是否按期、身份是否完整分别派生，不回填任何已失去的原 seal。

## 双钟、资源和证据预算

原 120/180/30 秒三个阶段、每例 G 的 20 秒窗口及最后 3 秒停止观察均不变。
PROBE 世代创建、唯一 probe、采样和退休全部计入 preparation 120 秒；C1–C6
的世代创建、采样、执行和退休全部计入同一个 cases 180 秒。最终 30 秒只做
登记对象收尾；不得为每代额外发放 30 秒。阶段剩余不足即停止，不启动已知
无法容纳的下一步。G 仍在原位置固定 17/20 秒双钟；退休不刷新该例时钟，也
不把外部后续清理补记成原 20 秒内成功。外层期限不得晚于所属原阶段截止。

每代执行前后采样共同 E 与当代四对象，显式绑定该代、准确身份和原双钟。
E 计数持续保留，不能因新建 G/B 将全轮累计成本归零；每代自己的计数不能
被当成全轮数据，也不能把 E 与子树层级计数简单相加而双重记账。memory/pids
事件、原 wait code 等只是原观察事实，不能单凭计数没有增加断言 SIGKILL
来自哪里。不新增 eBPF、内核追踪、包安装、宿主配置或附加实时探针。

仍为每例双流 128 KiB、六例 768 KiB、其他诊断合计 256 KiB、报告 2 MiB、
普通文件逻辑 32 MiB/128 项、事件每回执最多 256 项、全部控制帧每例最多 128
帧。新字段和退休记录计入原预算，不增加旁路原流、无界内存或 artifact 文件。
原 allowlist 保持；原件保存失败或结构超限必须显式失败，不能静默丢字段后
声称完整。实际 blocks/inodes 观察仍不等于原 Q2 文件系统峰值证明。

## native v2：早退、拒绝与独立事实

新 helper 的 native 回执使用显式 `schema_version=2`，增加固定 `generation`
字段，取值只能是 PROBE/C1–C6 且必须与 kind/case_id 一致。原控制帧 version 1
和病例意图不改变；新诊断不是可从外部请求的控制命令。旧 native v1 保留原
校验分支，不通过扩大旧事件集合使旧回执悄悄拥有新语义。

新增的事件名和参数意义固定：

- `s_exit_before_arm`：仅原 S pidfd/原 wait 已观察、此前没有通过武装核验时产生；
  参数保留原 wait code、原退出已观察标记及 REQUEST 已发送计数。它不证明信号来源。
- `s_arm_rejected`：收到准确 K_ARMED 但身份/降权核验失败；参数是固定拒绝原因
  枚举、已通过的核验位集合、未取得/失败的位集合。具体有限位表在实现审查中
  固定；不携带外部路径、任意 errno 文本或凭据。未取得不编码成已通过。
- `kill_requested` / `kill_result`：每次固定 B kill 的发起方、固定关闭原因、
  尝试序号及结果/errno 分别记录。原 `b_kill` 继续只代表 G 那次写成功的事实；
  不把“打算 kill”或外部 T cleanup 当作它。所有退出/拒绝分支的原始 kill 都有
  固定留证责任，不因诊断失败建立重试环；留证失败本身进入未知并受原有有界收尾约束。

这些事件不得制造 `s_credentials`、`s_armed`、worker 身份或已封闭事实。G 对
未武装 S 的提前退出使用明确非预期关闭原因，不能仍以正常 C1 关闭原因输出
`fenced=1`。native v2 的 `g_summary` 三个事实位明确使用 -1=unknown、0=false、
1=true；缺 launcher 身份时 identity 不能依靠“零 worker”被补成 true。C2 的
已武装且没有创建 worker 与此前未武装退出是不同事实。独立收件器重新派生
每个位，缺证保持 unknown/false，矛盾仍报错；摘要永远不是接受身份或 fence 的来源。

native v2 要保留正常两个 worker、固定 C2 barrier、C3 丢身份、C4 S 崩溃、C5
有限 burst 和 C6 G 崩溃的原判据。新诊断不会把非预期早退改为负例通过；也不
因为已树空和原流 EOF 就将 C1 的 `case_expectation_met` 改 true。

## report v3：失败保留、世代账本与严格版本

顶层显式 `schema_version=3`。沿用源身份、账户、limits、原 run、capability、
cases、budget、cleanup 等职责，增加世代账本及下列有限失败字段：

- `primary_failure`：无失败时显式 null，否则只能有一条；记录固定 phase、
  generation 或 null、固定 code、最多 512 UTF-8 bytes 的非秘密说明、观察到它的
  MONOTONIC/BOOTTIME，以及可选的原 native 事件引用。观察时刻不冒充未记录的
  故障实际发生时刻。首次设置后不被后续清理、预算或收件错误覆盖。
- `validation_errors`：独立校验错误最多 16 条，合计文本最多 4096 UTF-8 bytes；
  每条固定 stage/code 与有限说明。超过界保留明确 exceeded 状态并拒绝资格，
  不以截断列表冒充完整错误集合。原 `reason` 只作受界的失败说明，不能在最终
  校验中抹掉首个失败，也不能在 primary_failure 存在时变成空成功原因。
- `generations`：至多七条、固定顺序的生命周期记录；每条绑定四对象与共同 E、
  配置读回、原 helper 完成/捕获、前后资源、native 回执身份与退休条目。未开始
  的病例明确未运行，不能添加伪造的 native 回执或清理成功对象。

新收件器严格区分“包的结构与来源可收件”“病例是否符合预期”“各项事实完整性”
和“最终是否获得资格”。可定位到原 S 的提前退出可形成准确的失败记录，但
缺失的账户/launcher 绑定仍是 unknown，不能省掉校验然后允许 qualification。
无法定位、字段矛盾、非法版本或超限继续拒绝收件。只有真实六例全部预期成立、
各病例合同必需的来源、世代、已登记账户和已取得原身份绑定完整，且本轮登记清理成立，才可能得到 `QUALIFIED_IN_FIXTURE`。C3 的规定身份缺失、C6 的规定 seal 缺失仍按原预期保留，不要求补齐；“必需绑定完整”不表示每个负例都达到完整监督成功。

新 v3 不再通过构造旧 schema 1/2 的浅副本来强迫新的世代账本适配旧“全轮同一
五对象”合同。旧 report v1/v2 与 native v1 仍走原冻结语义，缺新字段不自动填
值、不迁移旧原件、不重新解释首两轮。为 v3 添加枚举和校验时，应复用不变的
底层有界解析能力，不能修改旧分支的资格语义。
