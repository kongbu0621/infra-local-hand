# 宿主 FD 准入修复与完整生命周期复核

本次继续处理 RT2 09b 的已留存失败；只做普通代码修复和离线验证。
09b 保持 CONSUMED_FAILED，H01/Q4/H11 保持 NOT_RUN。没有 SSH、VM 操作、新窗口或原 caller 重放。

## 已完成的普通修复

`q2_journal_growth.py` 在本地预检的控制命令前、以及 execute 写消费标记前，分别检查
完整维护生命周期的 FD 余量。以同一锚目录 FD 创建至多20个短期副本，逐个要求编号小于128，
随后全部关闭副本；不读取额外路径、不枚举宿主进程、不关闭任何原保护 FD、不提高限额。
缺额返回 `GROWTH_HOST_FD_BUDGET`，包含阶段、原限额、所需及实际可用槽位。
预检成功不能替代执行前检查。该检查阻止已知不足的执行，不解决原长期持有集合过大的事实。

20个槽位来自：最紧的 post 构造之前，新保留输出及新 VM pidfd 共9个，selector 1个，
Popen 的 `/dev/null`、两组流管道和 exec 错误管道共7个；另留3个给有界身份/用量读取。
这不是对未来新实现的免检证明；新增对象必须重新核算全生命周期。

传输构造的输出创建、selector 创建、Popen 和 pipe 注册均进入同一个异常路径。
发生异常保留构造阶段和是否已有进程的信息；临时 I/O 关闭，已创建的证据仍由 Store 持有。
不重试、不向进程发信号；已启动进程继续保留在原 COMMANDS 记录中。
这些诊断仅描述未来调用，不能回填旧09b的具体失败 syscall。

## 实际离线验证

- 在隔离子进程设置真实 `RLIMIT_NOFILE=(128,128)`，构造116个基准 FD；原 pre 路径
  在 Popen 构造处真实产生 EMFILE，未启动合成 peer。没有使用 SSH 或 VM。
- 80、108个已占 FD 可准入；109、116、121个拒绝。副本关闭后 FD 集合与原身份完全相同。
- 五个构造失败点逐一覆盖，检查临时 I/O 已关闭、原输出保留、错误阶段准确、重复 close 安全。
- 合成协调器验证预检和消费前两种拒绝都不创建标记、不发传输、不执行任何现场 effect。
- 最终相关回归：**592 passed / 13 skipped**；其中初始三个测试文件为87 passed。
  这是本地离线结果，不能作为新候选安装、现场或核心 PASS。

## 原模型无法只靠一个临时 FD 优化解决

旧09b预输出前下界116，新一代需保留其五件返回，变为121。完整完成时新增九件输出和
一个新 VM pidfd，即长期持有下界131；即使不建临时管道也超过128。
原 post 构造下界为116+17=133；加入新一代后为138。不能把只延后 selector 的改动宣称为完整修复。

最小后续方案将55件历史维护原件的持续 FD 持有交给一个受限、同权限、随调用结束的子进程。
先由 fork 继承原 FD，子进程确认持有后父进程才关自己的副本；文件描述身份始终存在。
所有原名称、metadata、链接数、不同 inode、bytes/SHA 检查保持。该进程安排和协议属于
待审变更，此次普通修复未实现或启用它。它必须计入原 CPU/RSS/进程预算，不能另开额度。

## 同时发现并纳入方案的标记大小

只保护读取已留存五份09b副本，与原私有索引重新交叉核对；事件
`RT2-09B-ORIGINALS-INDEX-REVIEW-20261009-01`。新索引仍私有，尚未公开其五项摘要。
实存旧标记63853 B。以其结构加入第十一代失败profile，保留双份历史时的离线样本为
66121 B，超过65536 B。该样本已足以证明旧序列化不适配，尚非完整新 manifest。

仅把 manifest.inputs 的重复 history 改为摘要引用、仍在 manifest.resume 保留完整一次，
同一样本降为54325 B，完整历史11870 B。未来 producer/独立 consumer 必须先校验完整历史
和引用，重建原完整 source binding 后再核对原 hash。不能只相信摘要、遗漏原件或提高上限。
新 custody 字段、来源、准确 A/C/D 和所有时钟宽度尚需在获准实现时一并验证。

新范围提案须合并解决 FD 所有权、标记去重、十一代消费及原核心接线；不能先开现场窗口试错。
当前普通修复没有为旧窗口或新09c授予执行权限。
