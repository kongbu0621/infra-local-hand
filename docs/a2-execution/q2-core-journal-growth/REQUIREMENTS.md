## 目标及已经核实的事实

只消除核心验收已定位的 journal 容量阻塞，保留已有数据和全部历史承诺。
[真实观察](../Q2_CORE_CAPACITY_OBSERVATION_REVIEW_20261006.md)的 journal 可用量为
229134336 B，四次已消费核心的条件门槛为 299892736 B，差 70758400 B。
如下一次核心仍采用原每批 journal 36700160 B，条件门槛为 **336592896 B（321 MiB）**，
相对已保存采样差 **107458560 B（102.48046875 MiB）**；这不是第五次执行授权。
维护副作用不能被这个仅含既有合同的数字隐去。

2026-10-06 本地只读核对了固定原计划、管理启动脚本、完整保存的容量输出及 journal 镜像头。
启动配置将独立 qcow2 作为 virtio journal 盘；保存的现场结果为整盘 ext4，不是 LVM 或分区。
当前本地镜像头两次稳定读取报告 qcow2 v3、64 KiB cluster、256 MiB virtual size、
无 backing 引用、无内部 snapshot、无加密及 incompatible feature 位。
这只是小范围当前头部观察，不是全镜像一致性检查或停写证明。
固定启动脚本为 `-monitor none`，没有 QMP；它本身也没有可靠的重复启动保护。

因此选择一次受控 guest 停机后的镜像增长，再启动原 guest、增长原 ext4。
不能在线修改被 QEMU 使用的镜像，不能绕锁、热补 QMP、换盘或改挂载来逃避原身份检查。
[QEMU 官方说明](https://www.qemu.org/docs/master/tools/qemu-img.html)要求修改镜像时不被运行实例使用；
增长镜像后仍需增长文件系统。[resize2fs 上游手册](https://github.com/tytso/e2fsprogs/blob/master/resize/resize2fs.8.in)
说明 ext4 在线增长有内核/文件系统支持前提；本方案不在失败时强制执行或更换工具路线。

`journal.qcow2`，身份来源和摘要见架构。journal 虚拟容量从 **268435456 B 增长到
536870912 B（512 MiB）**；不得缩小、格式化、重新分区、变更 UUID、权限、配额或挂载点。
原四盘唯一 guest 虚拟总量由 29259464704 B（27.25 GiB）变为 29527900160 B（27.5 GiB）。
原 [Q1 容量结论](../E3_QUOTA_Q1_GUEST_CAPACITY_REVIEW.md)保持历史有效，不能继续称新 fixture 为原容量未变。

交付是一次准确 D 的受控维护及其结果：原 journal 完整离线备份、扩容前后身份/目录内容摘要、
各步骤返回和最终普通可用量。目标是 journal **可用至少 400 MiB、32768 inodes**，
且其余固定 parent 的身份和容量没有新拒绝；512 MiB 虚拟大小不自动满足此目标。
400 MiB 相对上述 321 MiB 留 79 MiB 规划余量，并非排他预留或全部未来义务的证明。
真实维护费用另列，不隐含批准增加任何核心任务预算。

J1 实现窄维护工具，J2 验证和准确冻结，J3 前置门全部通过后进行一次维护。
允许最多一个永久消费 marker、一个正常关机请求、一次受保护的 VM 启动、两次固定 SSH exec：
第一条为关机前检查和条件关机，第二条为启动后检查、条件 ext4 增长及最终回收。
第二条是明确计入的新维护阶段，不是重试旧 carrier；两条各 ConnectionAttempts=1，均无重连。
不单独探测 SSH 端口、不增加第三条连接、不补采、不换名重试。任一前置失败即不发后续动作。

## 必须显式接受的维护边界

这次会中断整个隔离 guest 并改变 boot identity，不只改变一个文件的长度。
只有当前旧业务域均静止、无未知业务 writer/自动恢复启动路径、且 journal 持久证据可保留时才允许关机。
不能证明就停止，不能通过关机把仍活动的未知任务变成“已退出”。不强制关机、kill QEMU 或强制卸载。
重启会失去易失内核/进程/tmpfs 状态并产生正常启动、SSH、sudo 和日志副作用；
备份只覆盖 journal，不是四盘一致性 VM 快照。历史退出、使用量和业务真值仍 UNKNOWN，不退款。
任何本来只有易失副本的必要旧证据必须在关机前判为阻断，不能用本批准解释为可丢弃。

为不覆盖旧 pid/串口文件或引入无限增长的新串口捕获，新启动仅将 pidfile 改为本次固定新文件，
并把 serial backend 改为 `null`。保留原串口设备和全部磁盘/网络/资源配置；不修改旧 start.sh。
这意味着此次启动及后续这个实例不保存串口原文，启动故障只能使用已有步骤返回和两次固定连接内的证据，
不能再补采；这是本方案明确请求接受的可诊断性取舍，不得称启动日志完整。

既有准入要求旧 boot 与 HELLO 对应；重启后**不得删除该检查或直接重放旧 package**。
本范围记录旧/新 boot 与同一 VM 的维护关系，只为维护结果采用新 boot，不授权核心准入采用。
下一次核心需另有准确的单次批准，明确维护代次接入、四旧核心、两旧诊断及本次维护的保留边界。
新的 pidfile/serial 参数也须由后续批准明确接入，不能声称原管理参数逐字未变。
H11 仍指新验收任务自己的原 ledger/原 unit；本维护重启不能冒充 H11。

容量/用量检查是应用限额及非排他观察，不是共享宿主全程物理上界。更早 host 历史承诺仍 UNKNOWN，
不以其完整性未知单独阻断本次维护，但不将其置零或称已释放。旧四核心与两诊断的 **264 MiB/80 inode**
host 承诺全额保留。源盘和备份在同一宿主故障域，不保证应对宿主介质故障。

## 新维护预算和期限

这些是新的维护预算，不替代或续期任何原核心批次预算。原核心每批限额完全不变。

| 项目 | 上限或准入规则 |
| --- | --- |
| journal 虚拟盘 | 精确 512 MiB；只增加 256 MiB |
| 完整 journal 备份 | 一个 create-only 文件，逻辑/观察分配各 ≤320 MiB，保留原字节；不使用 reflink 冒充独立副本 |
| 增长后 journal 镜像 | qcow2 逻辑/观察分配各 ≤576 MiB；原虚拟内容与新空间在此池内，不再次相加 |
| 新 host 控制及证据 | 合计 ≤8 MiB/32 inodes，含 marker、两个阶段双流、receipt 和新的 pidfile；单 stdout/stderr 各 ≤1 MiB；serial 为 null，无新串口文件 |
| host 当前可用条件 | 涉及每个设备至少保留旧 264 MiB/80，再加备份 320、整个目标镜像 576、capture 8、维护余量 128 MiB/256 inodes，即 **1296 MiB/370 inodes**；同设备去重、不同设备保守完整计入 |
| guest journal 内容比较 | 每次 ≤256 MiB 文件内容、≤32768 条目，不跨挂载、不跟随链接；前后各一次 |
| 控制进程 | 单进程 AS 256 MiB、FD 128，新增同时活跃控制子进程 ≤8；不新建 guest 服务或管理平台 |
| 维护观测预算 | 新管理工具 CPU 合计 120 CPU-s、峰值 RSS 512 MiB；保留实际已取得计量，缺项 UNKNOWN；不称其覆盖 QEMU/内核/管理祖先 |
| 原 VM 配置 | 仍 4 vCPU/8192 MiB；不扩大，不当作本次管理进程 RSS 或整机峰值证明 |
| 新窗口 | 首次 J3 本地预检起同一双时钟 900s，780s 后不启动新的状态改变，余下用于已启动步骤观察和封存；单连接 ConnectTimeout 10s |

128 MiB 维护余量是风险预留/当前可用检查，不是已证明的启动审计硬界，不从 journal 的 79 MiB 余量抵扣。
预检和每步前后观察分配/容量；超限停止后续步骤。并发写、文件系统元数据和不可中断 I/O
可能在两次观察间突破应用阈值；此方案不承诺空间排他性或任何失败后的原子回滚。

**对正在修改镜像或文件系统的工具，不用超时 SIGKILL、RLIMIT_CPU/FSIZE 杀进程来假装安全硬限额。**
超过上述观测预算/窗口，状态为 INCOMPLETE/UNKNOWN，停止后续启动/连接/写步骤，保留现有进程身份和证据，
请求单独恢复决定；底层操作可能继续，不能宣称已安全停止或借机开始新窗口。这个维护安全边界与只读 reader 不同。
本地捕获仍有长度界，超限不无限排空；断流不证明远端 mutator 已退出。

## 成功和失败

只有身份/内容保留、离线备份、镜像检查、两层增长、当前容量和结果回收全部通过才记
`JOURNAL_GROWTH_VERIFIED`。它不是业务成功、完整 core admission 或生产支持。
失败留存原文件、备份、部分输出及消费标记，不自动缩回、回写备份、重启第二次或清理。
备份恢复本身需新的准确恢复授权；可能停留在 guest 已关机、镜像已长大但 ext4 未增长等中间状态。
支线暂停，production `E3_SUPERVISION_UNVERIFIED` 保持；本范围 H01/Q4/H11 执行数必须为 0。
