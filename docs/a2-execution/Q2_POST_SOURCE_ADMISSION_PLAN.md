## Wrapper：明确的兼容性差额

准确 T01 使用 `#!/usr/bin/env bash`。当前
[`memory_wrapper_argv`](../../tests/e3_host/q2_host_window_delivery.py)只支持三个明确 shell 路径，
故在解释器校验即返回 `HOST_WINDOW_WRAPPER_INTERPRETER_UNSUPPORTED`。
原脚本还有固定字面赋值的局部变量；现实现明确不推断局部赋值，不属于其环境变量白名单，
因此即使仅放宽第一道检查，仍会命中 `HOST_WINDOW_WRAPPER_ENVIRONMENT_UNSUPPORTED`。
未发现现有适配器列出的脚本文件自省、eval、source 或间接展开 token；这不构成通用 shell 安全证明。

这不是读取失败，也不能靠再次收集相同原文解决。后续需证明原脚本在准确解释器、argv、
工作目录及环境下的等价关系，先界定支持范围，再审查适配实现。不得为适配而修改原脚本、
绕过脚本构造另一套 SSH 命令，或把“允许取得原文”升级为“允许执行”。

## H07：需要覆盖的具体调用顺序

[`q2_startup_retry_entry.py`](../../tests/e3_host/q2_startup_retry_entry.py)的首次远端 probe
先于 anchor 建立，之后才发带相对 `RuntimeMaxSec` 的工作单元；collection 又是该单元外的另一条调用。
因此后置工作单元不能证明首次远端、排队、传输、初始化与 collector 已受同一原始绝对截止保护。

[`q2_supervisor.py`](../../tests/e3_host/q2_supervisor.py)明示范围为 `TARGET_CONTROLLER_CLOSURE_ONLY`。
其 finally 仅在取得 original 运行身份时调用 `stop_original`；排队/启动期间尚未绑定 original
即失败的路径，没有由这一清理分支证明独立撤销与截止后不再激活。已有停止原语可研究复用，
但不能把窄范围控制器监督器直接当成 H07 全链证明。

下一方案必须说明保护如何在首次远端前生效，并验证迟激活、无 original、传输停滞、
boot/双钟不符和客户端失联等反例；不得先 probe 再建立保护，或在迟到激活时刷新相对时长。

## 文件系统：当前实现的支持范围也不匹配

rerun3 的 host parent 报告 size=12,288、blocks=24，即当前分配 12,288 bytes；
flags=528,384，为 EXTENTS 与 INDEX 的组合。它是本次观察的事实，不是永久属性，
也不能据此推断哪些后续动作造成变化。

当前 [`filesystem`](../../tests/e3_host/q2_host_window_record.py)限定只有 EXTENTS 标志，
且 parent 的逻辑及分配量均为 4,096 bytes。因此本次报告的 flags 和几何分别超出该支持范围。
writer 还保留 root-only 身份、raw-device/superblock 资格及完整事实门；不能假称现场实际
已经调用 writer 并在某个后续谓词失败，也不能只修普通身份支持便宣称可消费。

现有 64 KiB marker 分配子上界不是 indexed parent、allocator/journal 全过程峰值的证明。
下一方案要逐项说明普通操作者、固定父目录、目录增长、对象分配峰值及持久性依据，
缺证则保持未准入。不要修改现有目录 flags、移动消费定位、请求 sudo、试写后删除，
或让用户把工作目录改成实现偏好的形态。当前差额也不证明预算必超或现有磁盘有故障。
