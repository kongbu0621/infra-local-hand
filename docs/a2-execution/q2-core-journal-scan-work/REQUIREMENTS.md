## 事实、目标和明确取舍

源码基线 `68b63da88d70cfb8151f66a75c7f523baaf012d2`；
[最新现场登记](../Q2_CORE_JOURNAL_MAPS_BUDGET_FIELD_20261007.md)位于
`8c58f093a3fc923fb078811622fb2691448e81fc`。MB1 已完成，MB2 已消费并在 checkpoint 1
以 `FD_TOTAL=262145>262144` 失败，marker false、SSH 0；journal 和 H01/Q4/H11 未启动。
此为截图支持的返回，未独立认证原始流。此前 maps 64 MiB 拒绝和本次 FD 拒绝均为首次
越界，不能据此求得全宿主需求；512 MiB maps 是否足够仍未知。

目标仍是完成原 journal 256→512 MiB 维护，解除核心验收的前置容量阻塞。整体验证发现：
旧 FD_TOTAL 在完整初始 snapshot 已经 stat 之后才累计，并未计入复核及匹配项额外 stat。
本次改为在真正的 FD 元数据操作发生前计费，并在同一次结果中保留有界扫描进度。
这解决已知工作量准入与诊断缺口，不证明 busy host 必然满足完整覆盖、期限或一致性条件。

本范围准确改变四项：

1. 用每个 writer 调用最多 **2,097,152 次 FD stat 尝试**的固定预算，替代旧事后累计
   `FD_TOTAL=262144` 准入。初始 snapshot、复核 snapshot、匹配对象额外 stat 共享此预算。
   原逐 task 检查、每 snapshot 65536 条目、maps 512 MiB、单文件限额及所有身份/writer
   谓词不变。不按 PID 去重、不缓存、不遗漏任务。不保留会先阻断的旧累计 FD 准入。
2. 结果协议显式升级为 `lhq-journal-writer-result/v2`，成功/失败各增加一个固定、有界
   progress 对象。只统计原有操作和已经取得的时钟样本，不加探针、读取或失败后补采。
3. 仅两维护实现源文件上限从 65536 B 改为 **98304 B**；固定 root payload 32768 B、
   wire/argv 65536 B、其它输入/输出及 bundle 限额不变。为绑定和诊断保留明确空间，
   不再靠持续压缩整个文件来挤入新逻辑，也不新增第三实现模块或依赖。
4. W1 完成准确绑定、验证、发布、候选 CI 和冻结后，沿用 `lhqjgrow-20261006a`、原输入
   和原对象，允许**一次**替代预检。全门通过后同窗完成未消费的原维护，无独立诊断试跑。

2,097,152 是请求接受的有限工程预算，不是根据 262145 测出的需求。它改变计量单位及
允许工作量，不能表述为“所有资源界不变”或“足够保证通过”；任何自动提额均禁止。
八个全成功检查点的这类 FD stat 尝试合计最多 16,777,216；这不是全部系统调用数量。

## 继承、停止和完成标准

继承原扩容 A `59948ec4fedb807a31cdbff77acc134e84414160`、宿主读取 A
`2b4448c7b89d1910840f7aee2ae2b781f970e179`、终端认证 A
`2b236865dc0a89e475c4021cac44d7193f252f67`、两替代诊断批准及 maps A
`d18b490a7cdb63ee43044a29a89746ef78fccff3` 的未受影响规则和历史字节。
仅上述四项在本方案将来被批准后发生替代；旧失败、窗口及历史 UNKNOWN 不改写。

- 原 Owner 真实前台终端和普通 coordinator 身份保持；只有固定只读 writer 使用现有
  sudo，密码只交给控制终端。不改权限、sudoers、服务、安装、凭据、SSH 或管理对象。
- 原每 writer 15s（含认证）、900s 总窗、780s 修改截止、八个串行单次检查点保持。
  AS 256 MiB、FD 128、控制子进程最多八个、120 CPU-s/512 MiB 部分观测及存储预算保持。
- 保留所有可见性、FD/flags、maps 格式、PID/TID/FD 身份与集合复核。任何未知、漂移、
  超限或失败停止后续步骤；诊断不能把部分扫描变成 PASS。
- 旧窗口全已消耗；新窗口开始即消耗。累计维护仍最多一个 marker、两条固定 SSH、
  正常关机/完整备份/镜像增长/VM 启动/ext4 增长各一次。失败不退款、不重试、重连、
  强杀、清理、恢复、回滚或另开窗口，不重复安装。

W1 必须证明实际操作预算正确计费、完整覆盖、原拒绝条件、v2 严格解析与各来源/长度界。
W2 只有完整备份、身份/内容保留、两层增长、普通可用至少 400 MiB/32768 inode 和原
合格 receipt 全部满足，才记 `JOURNAL_GROWTH_VERIFIED`；否则记录首因和已取得的前缀。

本范围不执行 H01/Q4/H11，不授权新 boot 的核心采用。该后续接线缺口已列入计划，
不能把维护成功误报为核心完成；namespace/watchdog、生产部署及支线继续暂停。
