## Implemented batch

retained-domain inventory, directory access, new-object absence and combined
resource costs before provisioning. A create-only intent precedes the new
ordinary identity, protected installation/state, seven quota roots, four system
parents and the instance-specific delegated ordinary manager/parent. Partial
objects are retained and do not become an automatic retry path.

The observed receipt feeds the actual policy/registry/allocation decoders and
an empty ordinary SQLite ledger. Fresh exec enters one original management
owner. Its child binds the actual MainPID, invocation and cgroup, performs the
complete fixture check, then enters the existing supervisor in that same
process. Original client exit, both stream EOFs and independent stop evidence
remain separate from the child's successful result marker.

The private single-file handoff contains a materialized shallow Git snapshot and
the exact candidate wheel. It uses the already supplied management SSH entry
and one finite root service; it creates no additional supervisor hierarchy.
The whole preparation service has a 600-second wall limit, 512 MiB memory,
64 tasks and 100% CPU. The later original owner interval is at most 120 seconds;
that interval is not mislabeled as a separate 120-second kernel service limit.
The private recipe charges the actual 512 MiB/64-task outer allowance. Private
guest identity, paths and original host evidence are not published here.

The lexical path validators now admit the literal `@` in an actual
`user@UID.service` cgroup while retaining canonical-path restrictions and exact
peer/parent identity checks. No broad path or namespace bypass was added.
