# Q2 账户准备失败后的限定接续：实施方案

- Authority：Owner；状态：**PROPOSED / Gate OPEN**；scope：`LH-Q2-PREP-RECOVERY-v1`。
- [需求](REQUIREMENTS.md) → [架构](ARCHITECTURE.md) → 本方案。
- 新范围关闭前仅编写文档、检查既有代码与原始证据；不新增可执行恢复器、恢复测试、配置或 prototype。原已关闭范围内的独立兼容性修复可继续，但不由其测试结果推导新时窗权限。

## 实施批次

| 步骤 | 交付 | 硬停止条件 |
| --- | --- | --- |
| G0 | 固定本三份文档 A；Owner 明确批准新恢复时窗及范围 B；单独记录 CLOSED 的 C | 无准确 R/A/B/C 不进入恢复实现 |
| G1 | 显式 `tests/e3_host/` 恢复合同、只读鉴证和接续入口；固定工具来源，生成私有恢复计划 | 不得改变原 plan、安装候选或原失败字节 |
| G2 | 校验旧意图、五项命令/步骤记录、现场主组/账户、全部未交付边界及合计容量 | 不匹配、额外 intent、未知副作用、期限或余量不足即 BLOCKED |
| G3 | 新管理 envelope 下 create-only 保留恢复 reservation；跳过已完成 groupadd，只执行更正 useradd 和原未交付准备 | 任一已消费对象或不明交付均停止，不循环重试 |
| G4 | 独立恢复回执贯通原装配；期限充分且原运行未发行时，进行唯一正常首次发行和监督运行 | 原运行记录存在、身份改变、预算不足均拒绝启动 |
| G5 | 收集新旧关联、原失败保留、恢复事实、运行及原外层退出/EOF；发布脱敏结论 | 不能将代码、模型或部分现场通过写成完整实机验收 |

## 实现合同

恢复工具无参数时只输出 BLOCKED。执行必须显式给出固定私有计划及摘要，计划只允许“主组成功、账户配置解析失败、后续全未交付”这个接续点，不提供一般重试或任意命令能力。

保留同一 preparation ID；recovery attempt ID 仅为追加证据身份。恢复日志使用原 reservation 内新子对象，累计旧文件与新日志的真实块/inode，原失败 receipt 不覆盖。候选安装和原运行代码仍使用原 source/wheel pins；恢复工具来源及差异单独进入回执。

鉴证阶段集中取得：guest/boot/namespace、原记录摘要、主组与账户状态、准确路径和 project 库存、user manager/父 slice 配置及运行状态、原装配和运行 reservation 缺失、Q1 保留清单、工具/候选和合计容量。使用当前固定工具和有限读取，不安装依赖，不更改已有文件系统。

本次管理 envelope 在首次持久恢复修改前保存：外部管理/捕获最多 300 秒，guest service 最多 270 秒且停止最多 3 秒，恢复鉴证/准备/装配最多 140 秒，尚未发行的原 Q2 owner 仍最多 120 秒。140 秒从 guest 恢复入口开始，首次鉴证读取前固定绝对 issued/deadline，鉴证耗时计入。CPU 总上限 300 秒、内存 512 MiB、PID 64、双流合计 2 MiB，且服从原较小对象/命令限制。各层使用固定绝对期限；所有阶段共同消费外层时窗。原计划 450 秒准备上限和旧失败保持，新 140 秒单列记录，不更新旧 deadline。

原正常首次运行保留现有 owner/supervisor/target/phase 的限制和发行次序。若剩余恢复窗口不足，保留已经完成的准备和独立结果，不启动运行、更不自动建立下一时窗。原 owner/handoff 记录一经生成，失败也不能删除后重发。

## 必需验证

| 风险 | 验证 |
| --- | --- |
| 已有对象冒充本 preparation 所有 | 错主组名/GID/成员、已存在账户或 UID、原命令摘要/退出/EOF 不符均在写入前拒绝 |
| 部分后续动作重复执行 | 注入额外 intent、已占 project、存在目录/manager/ledger/handoff；全部拒绝；证明 groupadd 永不再次执行 |
| 原失败被修饰为成功 | 比较全部旧文件前后摘要，原 `INCOMPLETE` 不变，恢复结果单独关联且装配保留 provenance |
| 来源或计划漂移 | 改 source/tree/wheel/tool/plan 任一摘要拒绝；独立恢复工具来源可审计，原候选保持 |
| 额外空间和时间被隐式补给 | 旧日志加新增日志/暂存的块与 inode 超限拒绝；过期新 envelope、单命令超时、运行剩余费用不足拒绝；不从当前空闲量发行新预算 |
| 初次运行被变成重试 | 任一原 owner/grant/operation/运行 reservation 已发行即拒绝；首次正常路径与缺失退出/EOF 分别验证 |
| 修正命令仍产生旁路对象 | 固定无登录账户参数与现场支持行为；核对 home/邮件等不在计划中的对象不产生，无附加组 |

测试分为无副作用合同/负例、真实文件与管道、准确安装贯通、实际 guest 恢复及运行。原有兼容性修复的测试不替代恢复边界测试。新增实现必须从独立 C 之后提交，测试报告绑定准确 committed source。

## 完成与保留

交付一个有界批次入口及完整结构化报告，集中完成允许接续的全部步骤；不要求用户逐项目录审批。若现场偏离限定接续点，保存完整原因及未交付列表，停止后不得自动改计划继续。

保留原准备失败、主组、旧 Q1 记录和所有新增恢复材料。成功仅表明本次限定恢复及明确记录的实际运行结果，不关闭 Q3、生产、GX10 或 E4–E6。清理/回收不在本提案内。
