## 账户证据的具体实现边界

1. 在原 preparation 双钟窗口内核验固定账户工具路径、字节摘要及本地解析来源；
   不调用包安装/配置命令，版本不能取得时明确留空和依据，不伪造版本。
2. 用有界固定观察单元取得精确 precheck；每个本地账户数据库≤256 KiB、输出≤8 KiB、
   单次≤2秒。最多五次观察共享原准备/清理预算。无法完成就保留原因和未知，不重试。
3. useradd 仍用已修复的 system/no-home/no-log-init/nologin profile，仅一次；保存原
   command_id、是否启动、原退出与 rc、超时/终止请求及双流完整性。创建前缺证不得执行。
4. 创建失败或捕获缺证后不进入 cgroup/probe；若原进程尚未退出，按已有有界收尾处置
   原进程，不能同时查完“不存在”就声明无副作用。未决始终阻断清理所有权的建立。
5. 全部创建成功后条件通过才登记 admitted_identity；其他情况下只有 observed_identity。
   部分账户/组不自动删除。清理前后的完整复核、共享组/UID 排除及后查沿用架构合同。
6. 每项观察、命令与证据的时间/输出计入原预算；预算不足标未取得，不刷新窗口。

每次固定本地观察还必须核对读取前后文件身份/大小/修改信息和解析完整性；NSS 点查
在同一有界子进程内，结果需与本地目标一致。解析来源的封闭集合已在架构固定为
passwd/group 各自 `files` 或 `files systemd`；不支持时在查询前拒绝，不通过更改
nsswitch 或账户策略使其通过。该 runner 实际来源是否满足仍是 F1 待观察事实。
显式 initgroups 同样准入；路径、文件所有权/模式及最多五类点查均依架构固定。
两秒窗口从启动前覆盖原退出/EOF/回收，未决观察禁止下一次观察或账户操作，
清理阶段不得刷新该观察期限或把迟到退出补为按期。
三个固定来源在观察前后整体复核，不宣称原子快照；userdel 后仍绑定原 admitted
UID/GID。systemd NSS 的内部工作属于明确的托管 OS 信任范围，不扩大到服务控制。
账户数据库是共享设施，身份元组无不可复用世代；无并行账户管理的可信 fixture 假设
必须进入报告。检测到变化或不满足假设时不作删除，不能声称竞态已被绝对排除。

## 离线验证与反向检查

继续全部旧 H07 负例，加下列与真实故障对应的定向 mock；不重复无关全仓审计：

- 观察/清理输出和时间耗尽：没有新窗口、额外查询或无限捕获；原证据保留。
- schema 1 保持旧判定；schema 2 缺字段/身份不一致/假成功/未知版本拒绝。
- 原首轮摘要不符、前序 boot 重复、round 回退、attempt>1、新 UNKNOWN 或额度不明：续验拒绝。
- C3/C6 预期缺证仅在其 cleanup 真实成立时保持原有限例外；其它病例判据不放松。
