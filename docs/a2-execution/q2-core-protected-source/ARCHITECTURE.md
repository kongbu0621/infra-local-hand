# 原核心的受保护源码接入

**PROPOSED / Gate OPEN / NOT APPROVED**；`LH-Q2-CORE-PROTECTED-SOURCE-v1`。
仅修复[需求](REQUIREMENTS.md)中的核心阻塞，复用原 RC 的维护/核心执行和三段身份来源。

## 文件接入与信任

十四份 host/guest 依赖从准确 D 提取，在冻结前准备于私有受保护目录。当前准确源合计
643058 B；最终版本必须重新核算，在 1 MiB/32 inodes 准备池内，超界停止。
执行器读取副本时保留原 O_NOFOLLOW、所有者/权限、单链接、大小、字节/摘要、FD/名称
和漂移检查。继续把副本与准确 D 及冻结 pins 逐项比较，持有到退出。
不改变工作区权限、不放宽受保护目录条件，不把“已复制”当作来源已核验。
原私有候选仅用于普通修复；发行版本仍须重新绑定最终 D、准确授权和完整冻结。

前置检查、持有、计量、异常处理、结果保存必须在同一实际调用路径验证。
测试保留真实文件打开与资源限制，只替代 VM/SSH 的现场效应；另外用原隔离管道
检查验证 owned-child 计量和完整 EOF。禁止模拟掉发生过故障的本地文件边界。
错误上下文仅保留已知调用阶段与有界路径/原因，不新增宿主或 guest 观察。

## 旧失败与新结果

旧 RC2 八件及原 RC1 freeze/terminal 原样留在私有原位置，PS1 离线核对字节和摘要；
新批准/冻结同时绑定经核对的旧失败摘要、零 SSH/无 marker/无 guest 流事实。
它们属于本地准入失败保留，不增加维护代数，不伪造 guest 或维护原件。
旧原件不增加到维护的 55-FD custody，也不放进 guest 成功返回槽；原件不清理、不覆盖。
新 guest 核验具有独立 create-only 调用记录、nonce、准确新 B/C 与顶层完成记录。
旧 B/C、失败返回或新普通测试成功都不能释放它。

历史安装与原成功启动来源保持；只有新 guest 实际成功才能生成当前 activation/v2。
更新 producer、独立 consumer、私有 freeze/finalizer 的精确授权与旧失败绑定，拒绝
使用旧 RC2 授权、旧失败流、仅摘要自报成功、源码漂移或缺少实际顶层完成的替换。
组合归档仍使用原逻辑成员与两个固定源码引用，guest 槽只容纳新成功核验；旧 RC2
保留关系由上述准确批准/冻结绑定，不能声称旧失败原件被该归档连续持有。
采用这个边界是因为旧调用仅在本地失败，没有 guest 或维护消费；不减少旧保留义务。

## 维护与核心发行

PS2 完成并退出后，保持同一冻结代码，仅用真实返回填入数据槽，再核验来源与完整
资源/大小才放行原 10c。仍需完整维护原件、custodian 退出、最终用量与实际顶层完成，
独立消费者通过才能发行原 07a；核心接口、任务语义与三案不变。
源、manifest/receipt、preflight、transition、approved-input、capacity、独立 dispatcher
与 entry/freeze 采用准确新授权及新增读取/源码准备费用，历史解析和旧结果不改。

原 55-FD custody、维护交接峰值 128/核心准备上界 126 保持；源码副本等量替换当前
guest 核验持有项，不增加维护 FD。原源码 98304/98304/16384 B、归档 524288 B、
marker/receipt/描述/transition 65536 B、压缩/展开 49152/393216 B、argv 65536 B、
preflight 4096 B、approved-input 1048576 B、核心包 33550320 B、v2 投影 4096 B 不变。
全部限额按真实新绑定和允许的最大返回重算；任何超界或未知都不能发行。
