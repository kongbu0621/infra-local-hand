## 批次行为

入口先在原宿主机自动核对旧 intent、报告、双流和原 guest 输入，确认退出 3
与两路 EOF 对应已知的账户参数失败。随后一次只读时钟探测和一次恢复交付，
不会自动重试或更换恢复身份。

guest 核对原记录、已创建主组、尚不存在的账户、后续目录与服务、quota 项目、
原候选及 Q1 保留对象。仅在限定状态完全匹配后保留恢复意图，跳过已成功的
groupadd，执行修正的 useradd 和原计划尚未交付的准备步骤。

恢复结果使用独立 `RESOURCES_RECOVERED` 回执，原 `INCOMPLETE` 回执不改写。
原候选的账本初始化和监督运行入口继续承担实际运行；新工具只完成恢复鉴证、
观察值转换及首次交接。存在旧运行记录、额外已完成步骤、身份漂移或容量不足时停止。

原计划内的请求模板时间已经过期，但该请求从未构造、提交或发行。恢复器在证明
原运行未发行后，按本次授权做唯一首次发行，记录旧模板时间、首次发行时间、
新有效期、原计划摘要、同一 operation ID 和实际请求摘要。原模板字节保持不变；
任何已有发行、重复目录或重复交接均拒绝，不能借此续期既有请求。

## 时间、容量与退出

- 外部管理窗口最多 300 秒；guest 服务最多 270 秒，停止最多 3 秒。
- 140 秒鉴证、准备和装配期限在 guest 入口、首次旧证据读取前固定。驱动继承
  同一绝对期限，同时检查 BOOTTIME，已消耗时间及挂起时间不会被退回。
- 原 owner 仍最多 120 秒。首次交接前必须留足 owner、停止与 EOF 时间，
  窗口不足即停止。跨宿主机与 guest 的时钟由一次往返探测保守绑定，
  不直接比较两台机器的单调时钟数值。
- 探测及恢复双流合计上限 2 MiB。恢复管理服务限制为 CPU 300 秒、内存
  512 MiB、64 个任务；原独立运行域仍按原计划各自计费，不能将管理服务限制
  冒充全部独立域的合计上限。
- 旧日志、旧暂存、新工具、安装和装配都计入原预算。装配前按真实当前占用
  预留文件与目录费用，最终 handoff 写入后再次核对实际容量及原记录保留。
- 捕获完成与远端停止分别记录。客户端退出 0 仍须有完整双流及封存的
  `SUPERVISOR_CLOSED`；缺失、超时或内部 `INCOMPLETE/UNKNOWN/BLOCKED`
  均不能得到完成报告。`RECORDED` 也不代表 Q2 验收。
