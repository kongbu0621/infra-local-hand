## 原始缺陷、修复期问题与失败保留

- **输入缺陷与修复期问题分开。** 阶段捕获、Evidence 祖先持久化原有的外层异常误判，均以保留且核对准确输入字节的独立 red 证实。R6 首版 Manager、manifest、client 清理修复引入的同类误判则记为修复期缺陷；初次交叉复核遗漏该场景，补充记录明确撤换对应候选结论，保留旧版本和原结果。最终使用显式本次主异常，正常调用不会继承调用方已经处理的错误。
- **探针构造错误不作产品证明。** 共享捕获初次 validation fixture 未初始化 Git，未启动产品子进程；补齐 fixture 后在未修产品上单独确认。client 首次假定新打开文件必然复用刚关闭编号，实际遇到更小空闲编号；改用明确 dup2 后，基线准确观察到复用对象被再次关闭。Manager 的外层异常测试首次误留一条 fixture 清理 raise，修正测试位置后保留三项清晰 red；原 `_capture_stage` 另用准确输入独立证实。
- **实际到达范围如实计数。** client 外层异常 red 只到首个 close 分支；最终通过另覆盖 context 和 download，不倒推三分支均已各自基线复现。Evidence 遍历 red 先在子 FD 未关闭处失败，不把后续未到断言写成已观察结果。
- **构建环境与依赖审计限制。** 全新构建 venv 的固定依赖下载被代理返回 403；本地缓存缺少 `setuptools==80.9.0` 的 wheel，未完成该全新工具链安装。随后使用逐项核对九个固定版本的既有构建工具链，在全新干净源码工作树构建；基础和 MCP 验收环境仍为全新。28 个 MCP wheel 均匹配冻结摘要并离线安装。缓存审计首版误要求 ZIP 目录条目也进入 wheel RECORD，修正为核验非目录成员后通过；失败脚本和日志完整保留，没有修改依赖字节或复制已安装包。
- **根汇总命令启动错误。** 首次结果汇总漏传 Python 解释器，记录器在启动脚本前收到 PermissionError；没有启动子程序，也没有完整命令记录。原始错误转录、空日志和未知计时事实保留，不补造退出码；另用正确解释器和新标签完成汇总。该错误没有重跑产品或改动源码。
- **编排与读取失败单列。** Evidence 初次测试遗漏模块搜索路径而 import ERROR，没有进入测试正文；修正调用后重新验证。只读文件定位、报告尚未生成和大段输出截断等情况不计作产品故障，不补造时间、日志或成功结论。
- **故障是受控注入。** 本地真实文件、FD、selector、pipe、子进程、SQLite、密码学与 loopback/SDK，分别配合合成 manager/issuer/回调及 I/O 故障时点。没有把这些结果称为真实磁盘故障、断电实验、真实 cgroup 或 E4 当前客户端交付。
