## 要求 Owner 决定的最小顺序补充

既有 startup A `47b351b2b943bf1d6f1c71cfeb031157a2eb70cc` 与对账 A
`c65ff4e25ea6373aabf8db25d304ee7614b96eb5` 都禁止失败后重新开始唯一窗口，
同时要求完整现场鉴证先于新持久写入。仅用 RAM 记“已开始”，无法在跨进程或
崩溃后保留窗口消费；提前落盘又跨过现有顺序。因此实机入口当前保持 BLOCKED。

本提案请求一次决定两个相互绑定的有限变化：

1. **完整 guest 联合鉴证前，允许 host 在本地预检查后排他创建固定消费目录和
   一份 immutable 意图，完整 fsync 并复核后才首次探测 guest。**
2. **固定目录创建成功定义该唯一批次的消费边界；此前仅 host 本地只读的
   `LOCAL_PREFLIGHT` 失败不消费批次，允许重新进行完整本地预检查。**每次本地
   检查先取双钟临时原点；成功创建目录的赢家必须沿用自己的原始采样，不能在
   创建时重采样。该赢家的全部本地检查、落盘和后续工作仍合计受原 300 秒/
   准备 140 秒约束。未取得目录的本地检查不触发远端、写新文件或声称已消费。

这两项决定仅对上述两个旧 scope 的首次持久写入顺序，以及“首次 host 现场检查
已经不可重启地消费窗口”的受影响语义作有限 supersede。主动新对象例外只有
固定 host 消费路径；取得它以前仅允许纯本地只读预检查。不能宣称所有原重试
语义都未改变。完整 guest 联合检查仍先于任何主动创建的 guest 业务/对账/state
对象；其它 host 持久材料也须等待完整准入。原已授权探测所用传输/管理域自身
审计日志的准确前置边界在下文一并明示，不能笼统声称所有操作系统日志都不
产生持久 bytes。
旧三文档原字节及决定保留，不产生通用提前写入例外。

startup C `d4a925c883672fadc7d1b10a8dfe58df18b922cd` 与对账 C

## 有限 host 子预留

提前白名单只有一个文件和一个目录。4 inode 是保守上界，不允许额外 lock、临时
文件、确认文件或替代目录；不得删除、覆盖或重命名替换。逻辑和实际分配分别核验，
包含目录、块取整及部分写入，不假设 4096-byte 块；不能证明分配上界就写前拒绝。

写前检查只涉及准确 host/boot、受保护父目录与设备、目标不存在、设备实际可用
bytes/inodes、全部已知 host capture 实际/承诺以及该记录的分配/同步峰值。
这是本提案明确允许的 **host 记录预检查**，不冒充 guest 联合准入。子预留仍在
原 capture 64 MiB / 4096 inodes 内；后续同一完整账单必须包括 host 已用量、
未用预留和 guest 全部费用，不再给 host 或 guest 另套一份总额度。合计不符时
保留已消费记录，禁止后续 guest 持久动作与发行。

外部双流仍合计 ≤2 MiB，不能用于抵扣持久分配；若输出意图/摘要，其 bytes 也
计入此原通道上限。guest 对账五文件的 state 1 MiB / 16 inode 独立保留，不能
跨类抵扣。联合鉴证失败时不另写失败文件或自动起 collector；仅保留消费标记及
原有界通道中可得结果，缺最终 seal 如实报告。

## 原传输与管理域的审计日志

本决定同时明确原先“首次持久写入”文字对前置探测日志的边界：只限已批准的
固定传输/管理机制在原只读探测过程中自然产生的审计记录，可在完整联合准入
以前产生；仍进入原 journal/capture 类及真实设备共同计费，不得到新额度。
派发前须有界保留其原日志峰值和收尾成本，未知不能按零通过。此项作为本准确
顺序决定的明示部分，不声称原模糊文字已经授予任意日志写入权限。

这不允许提前创建任意诊断文件、业务状态、额外服务、日志设施或改变 journald/
SSH/systemd 配置。实际使用的机制若需要这些新动作，仍 BLOCKED。其它 guest
主动持久操作继续等待完整联合准入；管理域日志也不能替代消费标记或运行证据。
