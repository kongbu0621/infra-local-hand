# Q2 唯一窗口的 host 持久消费记录：实施方案

- Authority：Owner；状态：**PROPOSED / Gate OPEN / AWAITING OWNER**。
- Scope：`LH-Q2-HOST-WINDOW-CONSUMPTION-v1`；R 与[需求](REQUIREMENTS.md)一致。
- [需求](REQUIREMENTS.md) → [架构](ARCHITECTURE.md) → 本方案。
- 当前仅文档与审阅；新 host 顺序的合同、实现、测试脚手架及 READY 私有载荷均在准确 B/C 后产生。

## H0：准确方案与独立关闭

保留旧 startup A `47b351b2b943bf1d6f1c71cfeb031157a2eb70cc`、对账 A
`c65ff4e25ea6373aabf8db25d304ee7614b96eb5` 的原三文档及全部批准链。新提案只有限 supersede 两 scope 的受影响首次持久写入顺序及取得固定消费
标记以前的纯本地只读重试语义，准确范围见需求；实机入口
继续在现场探测和新持久写入以前 BLOCKED。不受影响的原已关闭实现/隔离验证可
继续，但不能当成新 host 顺序已获准或已验证。

需求已固定唯一 host 父目录的原 carrier 摘要/长度/AST 常量及当前 host boot
回传的准确摘要/长度/字段。新 A 明确采用此当前 host pin，不倒写历史或改变
原 guest boot pin；实施必须从原 bytes 复算，不能留给调用者自由选择。

提交三份确定字节为新 A 并登记摘要；Owner B 明确原 R、准确新 A、scope、固定
host 提前记录、标记前纯本地重试、原管理日志边界与同一唯一批次，保存准确
原话、时间/event ID 和稳定来源。独立 C 只登记关闭，不改 A 或混入实现；D 从
新 C 继续并单独固定源码闭包。未有 B/C 就停在 H0，不拿对账 B 代替，不先运行
RAM-only 现场预检来消费另一个窗口。

既有对账 D `8fd84521cdd25b455ff148e0c0fed6b5d8e39fe1`（tree
`5fb64e578d06e2954c1eedbc1b15e00069dc32a4`）已固定；隔离验证 154 PASS、
2 SKIP，旧相关验证 115 PASS。其 host 入口仍 BLOCKED；这些结果不证明新顺序
已实现、任何 guest 已探测或唯一批次已发行。

## 对既有对账 P1–P6 的影响

P1 来源分类、P2 全部 guest 事实和两目标 C/A/U、P3 五文件/state 子预算、P4
不受影响验证都保留；P2 完整账单同时纳入 host 消费及后续 host 捕获/封存。
原已授权探测的传输/管理原生日志仅在需求明确的前置范围内计费；不新增设施。
P5 增加“带临时双钟的本地只读检查 → 固定排他消费且沿用赢家原点 → 意图同步
→ 首次远端探测”，并明确只有取得消费标记以前的本地只读失败可以重新检查；
完整 guest 准入仍先于主动创建 guest 业务/对账/state 对象。P6 增加 host 消费和
实际文件 seal 关系，
原发行/stop/EOF/guest seal/验收仍独立。没有第二次运行或新的 300 秒。

H5 严格执行：离线固定输入 → 本地只读检查前临时双钟 → host 预检查 → 排他消费
及完整同步 → 首次远端探测/一次保守跨钟 → 原完整联合准入和共同账单 → 原对账
seal/再次准入/安装装配 → 唯一 owner 发行 → 原期限内各级收尾和封存。任何一步
失败保留实际边界。消费以前只允许重新完整本地只读检查；赢家不得在创建目录
时重采样，消费以后不删残留、不换名、不刷新时钟、不自动起另一个 collector。

## 必须验证

| 反例或边界 | 必须结果 |
| --- | --- |
| 新 A/B/C 缺失、D/wrapper/工具/计划摘要不同、原 carrier/host pin 不符、改 attempt/manifest/输出目录可换消费定位 | 现场读与写以前 BLOCKED |
| 两进程争用，既存空目录/文件/symlink/部分意图/同值完整记录 | 至多一个赢家，其余不探测不执行；不能删除/接管/换名 |
| 目录后崩溃、短写、file/parent fsync 失败、写满 | 部分材料消费且计费，禁止远端调用 |
| 分配上界不明、块粒度使 64 KiB 不足、inode 超界 | 创建前拒绝，不写后删除试探 |
| host 预检查成功但 guest 不全或共同费用超限 | 留消费标记，不做 guest 新持久动作/发行 |
| 从 state 或双流池抵扣记录，host/guest 重复套总 ceiling | 拒绝，按准确类别/设备唯一计费 |
| 固定目录前纯本地失败、另进程重新调用 | 尚未消费，只能重新完整本地检查；无远端/新持久副作用；赢家使用其检查前原点 |
| 固定目录后任一失败、重启、漂移/暂停、原截止已过 | BLOCKED/UNKNOWN，无接管、第二次派发或时钟续期 |
| 受保护路径替换、硬链接、内容/权限漂移、缺 O_NOATIME | 拒绝，无时间戳恢复或保护降级 |
| 远端迟到/排队、到达后刷新硬期限、未留有限收尾预算 | 派发/入口拒绝，不另起 270/140 秒 |
| SSH kill 被当远端停止、缺 EOF/stop/树空、局部成功补判 Q2 | 各自保留 UNKNOWN/INCOMPLETE，不重发 |
| seal 只核 RAM、漏真实成员/部分写入/自引用、超时补封 | 不封存，保留原件和缺项 |
| 未留原管理日志成本、借审计名义新建服务/日志设施 | 不派发、不增加权限或额度 |
| 联合准入失败后另落诊断、另起 collector 或换窗口 | 拒绝，提前白名单仍只有目录与意图 |

真实本地验证涵盖独立进程竞争、父目录/文件同步故障、held fd 名称替换、actual
blocks/inodes 和 O_NOATIME；模型验证涵盖双钟/跨钟、迟到和有限收尾。环境不
支持明确 BLOCKED，不以模型 PASS 代替持久性、guest 硬期限或独立停止证明。
测试只扩展至受影响接口，原冻结 runtime 验证保留其准确版本与边界。

H4 不证明已发行；B/C 不证明联合准入已满足。H5 一旦消费，即使没发行也不再
自动开始。H6 分别报告窗口消费、联合鉴证、对账 seal、发行、退出/EOF/独立
stop、各级 seal 与 Q2；原两次 INCOMPLETE 和所有来源/元数据限制不变。超出准确本地预检查分支的重试、更多
提前写入、额外对象、扩预算或第二个已消费窗口均须按原 R 处理新的受影响决定。
