# Journal 诊断替代窗口架构

状态 **PROPOSED / Gate OPEN**；范围仅来自[需求](REQUIREMENTS.md)。
复用既有维护 CLI、终端认证、root writer、八检查点和两阶段 guest 协议，不引入新管理组件。

## 诊断与执行不混同

现有批准范围内完成的诊断开发继续独立验证，不追认已结束现场，也不据修复推定历史原因。
生成 payload 与源函数保持同一拒绝语义；已校验的固定 reason/errno 可传到父层。
失败报告仍使用有界固定 schema，不保留任意异常原文、私密路径或 maps/cmdline/environ 内容。
缺失、畸形或不匹配报告仍拒绝；没有真实退出/EOF、扫描完整性或身份匹配就不能进入下一步。

新授权仅绑定一次替代窗口。执行候选 D 必须承接独立 C，冻结准确代码、payload、argv、工具及
原输入；如需更新本范围的授权绑定，仅登记准确 A/C，不顺带改变认证、读取或维护能力。
原窗口记录和批准文档不改写，旧部分 binding 不补造为新窗口，也不以改摘要制造额外窗口。
当前源码仍登记原终端认证 A/C；增加本范围绑定时必须保留旧 pins 和祖先关系，不替换旧批准。
源码长度上限保持；如为绑定腾出空间，只能作经验证的无语义压缩，不能删安全校验。

## 单次原流程

先完成原静态准备和真实 TTY 资格检查，不发 sudo/SSH、不创建 marker。
唯一新预检开始时保存真实 host boot 和两时钟起点；execute 只接受该次原私有交接绑定。
发现旧目标文件、超期、终端/host/输入变化或任何原准入失败即停止，不删除、换名或重开。

只在全部原预检通过后，进入原已批准维护：正常关机、确认退出与离线状态、完整备份、一次
镜像增长、一次原约定配置启动、原被动等待、一次 ext4 增长、内容和容量验证。
原双阶段 SSH、继续令牌、正常锁和不可强杀 mutator 的边界不变。

预算完整继承原三范围：15s/900s/780s、原 host 每相关设备 1296 MiB/370 inode 条件、
旧承诺 264 MiB/80 inode、备份 320 MiB、镜像 576 MiB、capture 8 MiB/32 inode、
120 CPU-s/512 MiB 部分观测、AS 256 MiB/FD 128、最多八控制子进程。
writer 输入/stdout 各 65536 B、stderr 4096 B、payload 32768 B；两维护实现各 65536 B。
这些额度不是新增池；历史承诺、管理祖先/TTY 计量限制及 UNKNOWN 不变。

失败保留首个已验证的具体原因、原有有界诊断、准确现场计数和已发生的修改。
观察超时或关闭管道不等于子进程退出；晚到认证仍受原 root deadline 拒绝。
不增加另一次诊断调用来解释失败，不自动恢复 guest，也不发 H01/Q4/H11。
