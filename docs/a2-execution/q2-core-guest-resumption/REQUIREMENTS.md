1. GR1：接入保留的成功启动和失败 guest 来源，采用已离线验证的 capture 完成记录
   修复，完成生产者/独立消费者、费用、来源、安装和边界验证、正常 PR 发布、准确 D
   的首次 CI及全部新 caller/来源/目的地/数据槽冻结。旧 caller 与 freeze 不变。
2. GR2：一次新的固定核验 `lhqguest-20261012a`。先按现有检查核对同一 host、原已启动
   VM 的 PID/starttime/exe/argv/namespace、镜像和信任文件，再只向原 Q1 端点发送
   现有六命令核验源码。新 nonce 在发行前冻结；仍只一次 SSH，无单独连通性探针。
3. GR3：仅 GR2 完整通过及最终数据冻结后，接续原未发行 11c 的一次预检，通过才
   同窗 execute；至多两次固定维护 SSH、一次已验证正常关机、原 journal 256→512 MiB
   备份扩容及一次原配置维护重启。保留原第十九份维护义务，不另加维护代次。
4. GR4：维护原件、实际 caller/coordinator/custodian 完成及两个消费者全部通过，
   直接发行原 07a，按 H01→Q4→H11 顺序执行。批内无需逐子步骤再批准。

这是**一次新核验的授权变更**，不是已修好的连接问题或旧批次重放。它不保证 guest
现在可用；若同一 VM 已不在、身份变化、核验失败或必要事实 UNKNOWN，则停止保留，
不得启动、改信任、补采、重试、清理、回滚、停止业务或改代码后继续本次现场。
